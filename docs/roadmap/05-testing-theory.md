# 05 测试理论与用例设计

> 测试理论不该停在背名词。它解决的是一个具体问题：面对一个功能，你怎么判断自己测得够不够？

## 为什么重要

用例设计能力是测开的「内功」。工具每年都换，框架各有流行，但「把一个需求拆解成完整、无冗余的测试点集合」的能力，是面试场景题和日常工作的通用货币。AI 能生成用例初稿，但判断覆盖是否完整、哪里被漏掉，靠的就是这一章（参见[第 10 章](./10-ai-assisted-testing.md)）。

## 知识清单

### 测试流程【必须掌握】

需求分析 → 测试计划 → 用例设计 → 用例执行 → 缺陷跟踪 → 回归测试 → 上线验证 → 复盘。每个环节的输入、输出和常见产物（测试计划文档、用例、缺陷单、测试报告）要能说出来。

### 测试分类【必须掌握】

按阶段：单元测试、集成测试、系统测试、验收测试。
按目的：回归测试、冒烟测试、探索性测试。
能画出测试金字塔，并解释为什么单元测试层应该最厚、UI 层应该最薄。

### 测试类型【必须掌握】

功能、接口、性能、安全、兼容性、易用性、稳定性。每类能举一个自己经历过的例子。

### 用例设计方法【必须掌握】

这是本章的核心，每个方法都要能「用出来说明适用场景」：

- 等价类划分：有效 / 无效等价类。
- 边界值分析：上点、内点、离点（最多 bug 藏身地）。
- 判定表：多条件组合（如风控规则）。
- 因果图：判定表的前置画法，了解即可。
- 状态迁移：订单状态机、审核流。
- 正交实验法：多因素多水平降维（兼容性组合）。
- 错误推测法：经验驱动的查漏补缺。
- 场景法：业务流程主线 + 支线。

### 缺陷管理【必须掌握】

一个合格的缺陷单：标题（一句话说清现象）、复现步骤、实际结果 vs 期望结果、环境信息（版本、环境、账号）、日志和截图、严重程度和优先级的判定。

缺陷生命周期：新建 → 确认 → 修复 → 回归验证 → 关闭（还有拒绝、延期等分支）。

### 测试左移与右移【必须掌握（概念）】

现代质量工程绕不开的两个概念：

- **左移（Shift-Left）**：把质量活动提前到需求和技术方案阶段。需求评审时识别可测性问题、开发设计评审时确认日志和接口可验证、CI 里前置静态检查。测开在左移里扮演「质量需求定义者」。
- **右移（Shift-Right）**：发布后继续保障质量。线上监控、告警、灰度验证、混沌演练、用户反馈闭环。测开在右移里关注「漏测问题如何被线上监控第一时间发现」。

这两个概念在[第 09 章](./09-quality-engineering.md)质量工程里会落地。

### 场景题答题框架【必须掌握】

面试很常见：测试电梯、水杯、登录页、购物车、微信朋友圈、红包、文件上传。别只按功能点罗列，按维度展开：

1. **功能流程**：正常路径和异常路径（主线 + 每一步的中断、回退、重复）。
2. **数据边界**：空值、超长、特殊字符、重复、非法格式、0 和负数、单位换算。
3. **权限和安全**：未登录、越权（水平 / 垂直）、敏感信息、频率限制、注入。
4. **兼容性**：浏览器、系统版本、网络状态（弱网 / 断网 / 切换）、屏幕尺寸。
5. **性能和稳定性**：高并发、重复提交、长时间运行、资源泄漏。
6. **可观测性**：日志、埋点、告警、错误码是否可定位。

这六维就是你的「测得够不够」判断框架，也是审查 AI 生成用例时的对照表。

## 学习建议与常见误区

- **用一个真实对象练透方法**：拿「注册功能」（用户名 6-20 位字母数字、密码 8-16 位含大小写、手机号格式、验证码 60 秒有效）写一份完整用例，把等价类、边界值、判定表全部用上。这一份用例练完，方法就长在手上了。
- **AI 可以帮你生成初稿，但你要会审。** 比如让 AI 生成登录页测试点，它通常会覆盖账号密码、验证码、记住登录这些常规点，但经常漏掉风控、频率限制、账号锁定、第三方登录、Token 续期、并发登录和审计日志。测开要能补上这些漏掉的地方——对照上面的六维框架逐项检查。
- **误区一：背方法名不练应用。** 「等价类是划分有效无效类」人人会背，但「手机号输入框的无效等价类有哪些」现场能列出 8 种以上的人不多。
- **误区二：用例越多越好。** 用例设计有冗余和遗漏两个方向的失败。1000 条互相重复的用例不如 200 条正交去重的。面试官会追问「这几条为什么不能合并」。
- **误区三：把缺陷单当通知。** 「登录有问题请看下」这种单子在真实团队会被打回。缺陷单的质量就是测开的专业名片。

## 自查清单

1. 说出六维场景题框架，并现场用它展开「测试文件上传功能」（限时 10 分钟，至少 30 个测试点）。
2. 边界值法：输入框允许 1-100 的整数，列出你要测的所有值并说明理由。
3. 判定表：优惠券规则「满 100 减 10、新用户再减 5、仅限周末」，设计判定表。
4. 状态迁移：画出电商订单的状态机（待支付→已支付→已发货→已完成，含取消、退款分支），并标出每个迁移要验证的点。
5. 水平越权和垂直越权的区别？各举一个测试用例。
6. 测试左移和右移各举一个你可以在当前项目落地的事。
7. 一条缺陷单必须包含哪七个要素？
8. 拿 AI 生成的登录页测试点，找出它至少 5 个遗漏点。

## 推荐资源

- 《软件测试的艺术》：测试经典小书，建立测试思维的第一本。
- 《Google 软件测试之道》：了解 SDET 概念的出处，读故事即可，不必照搬实践。
- ISTQB 基础级大纲：用例设计方法的系统化梳理，免费可搜，当索引用。
- [测试窝、TesterHome 社区](https://testerhome.com/)：中文测试社区，看真实测试团队的实践文章。
- [AI 测试开发导航 · 精选课程](https://www.testfather.cn/courses)：用例设计与测试理论实战教程，与本章配套。
