# 测试开发学习路线总览（2026 版）

> 一条从零基础到测试开发工程师（SDET）的完整路线：传统测试开发核心能力 + AI 时代的新赛道。

## 全景路线

| 板块 | 修炼境界 | 定位 | 覆盖内容 | 章节 |
| --- | --- | --- | --- | --- |
| 🧭 认知 | 💨 练气期 | 建立岗位判断力 | 测开做什么 · AI 时代变了什么 | 第 1 章 |
| 🧱 筑基 | 🧱 筑基期 | 编程与工程功底 | 计算机基础 → 编程语言 → 工程基础 | 第 2-4 章 |
| 🧪 测试核心 | ⚗️ 结丹 → 👶 元婴 → 👁️ 化神 | 从用例设计到质量工程 | 测试理论 → 接口自动化 → UI/App 与性能（并行）→ CI/CD 与质量平台 | 第 5-9 章 |
| 🤖 AI 时代 | 🦋 婴变期 | 提效与新赛道 | AI 辅助测试 → AI 应用评测 → AI 质量工程化 | 第 10-11 章 |

> 阶段六、七可以并行学习；从阶段五（接口自动化）开始就可以用 AI 提效，不必等传统技能全部学完。
>
> 🎮 修练须知：各位道友，境界不靠打坐，靠每章末尾的「自查清单」渡劫；跳级容易走火入魔，收藏不学则道基尽毁 😄

不要一上来就学一堆工具。工具可以很快上手，但测开真正拉开差距的是三件事：

- 能不能写出可维护的测试代码，少写一次性脚本。
- 能不能把自动化接进工程流程，跑在 CI 和日常回归里。
- 能不能解释一次失败背后的原因，给出日志、数据和链路证据。

## 三条定制路线

不同背景不需要把 13 章从头读到尾，按自己的情况裁剪。

### A. 功能测试转测开

你的优势是业务理解和测试思维，短板是编程和工程化。

1. 重点补：阶段二（编程）、阶段三（工程基础）、阶段五（接口自动化）——这三块决定你能不能跨过「会写代码」的门槛。
2. 快速过：阶段一（挑薄弱项）、阶段四（你已经会用例设计，补方法和术语的体系化）。
3. 选学：阶段六、七、八按目标岗位补，建议至少精通一个。
4. 必学：阶段九、十，AI 是功能测试转测开最好的差异化叙事。
5. 项目优先做[项目一（接口自动化框架）](./12-project-practice.md)，它和你的业务经验衔接最自然。

### B. 后端开发转测开

你的优势是代码、数据库、链路和日志排查，短板是测试思维和质量体系。

1. 快速过：阶段二、三基本可以跳过，只在单测框架（JUnit / pytest）上确认熟练度。
2. 重点补：阶段四（用例设计方法）、阶段五（接口测试的断言设计——不是会不会调接口，而是断什么才算验证了业务）。
3. 系统学：阶段八（质量平台与精准测试，最能发挥你的开发优势）、阶段十（AI 应用评测）。
4. 面试表达注意：把叙事从「我开发了什么功能」切换到「我保障了什么质量」，参见[第 13 章](./13-interview-guide.md)。

### C. 校招零基础

时间相对充裕，目标是体系完整 + 有一两个能讲的项目。

1. 按顺序走：阶段一到五完整学，不要跳。
2. 算法别回避：测试开发依然是技术岗，笔试和一面遇到算法题很正常，阶段一里的算法清单要练到位。
3. 项目做扎实：大二/研一就开始做[项目一](./12-project-practice.md)，后面每年递进一个，毕业时就有 2-3 个完整项目。
4. AI 两章尽早读：建立判断力不需要先会写代码。

## 3-6 个月学习节奏

按每天稳定投入 2-4 小时估算：

| 时间 | 目标 | 关键产出 |
| --- | --- | --- |
| 第 1 个月 | 补基础 | 一门语言入门，能写脚本和单测；HTTP、Linux、MySQL、Git 过一遍。标准：写得出代码、看得懂日志、调得动接口 |
| 第 2 个月 | 测试理论 + 接口自动化 | 系统练用例设计，完成一个接口自动化框架，接入测试报告和 CI |
| 第 3 个月 | UI 自动化 + 性能测试 | Playwright 主流程做稳 + 一次完整压测报告，二选一也可 |
| 第 4 个月 | 质量工程 | Jenkins / GitHub Actions、Docker、覆盖率，把前面的项目接进流水线 |
| 第 5 个月 | AI 测试 | AI 生成用例、审查代码、分析日志 + 一个小型 RAG 或 Agent 评测项目 |
| 第 6 个月 | 简历与面试 | 项目改成面试版本，刷场景题、算法基础题和项目追问 |

时间不够时的优先级：**编程语言 > 接口自动化 > 测试理论 > Linux / MySQL / Git > 一个完整项目**。UI 自动化、性能测试、AI 评测和测试平台按目标岗位补。
