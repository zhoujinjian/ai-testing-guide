# 01｜自动化测试能带来什么价值？你的团队为什么要做自动化？

> 开场先破一个误区再立价值：**自动化的价值不是「发现更多 bug」**——大部分 bug 在自动化建成前就被人发现了。它的核心价值是把人从重复回归里解放出来、保证已有功能不被改坏，同时把人做不到的事变成可能。

## 回答思路

### 第一步：价值分三条讲

| 价值 | 说明 |
| --- | --- |
| **效率** | 回归从两天缩到两小时，提测当天就能出冒烟结果 |
| **覆盖** | 并发、大数据量、长时间浸泡——人力不可及的场景只有自动化能做 |
| **信心** | 每次发布前自动回归全绿，给团队稳定的质量信号 |

### 第二步：马上补 ROI 账

自动化不是免费的——用「每次回归节省的人工小时数 × 频次」对比「建设维护成本」，**回收期一年内的才值得做**。这个账会算，面试官就知道你不是脚本狂热者。

### 第三步：带一个自己项目的真实数字

比如核心回归集三百条、跑四十分钟、每次发布省两个人天——**数字一出，真做过和背概念立刻分开**。

### 收尾：给克制观点

自动化是质量工具箱里的一件，不是全部——新功能探索、易用性、主观体验依然靠人。全盘自动化的口号式回答反而减分。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 企业被「上自动化烂尾」坑过很多次，这题先筛掉两种人：把自动化当万灵药的，和无脑写脚本不算账的 |
| 过线标准 | 价值讲清（回归解放人力 + 人力不可及）+ 有成本意识 |
| 区分度 | 能报出自己项目的真实数字（用例数、耗时、节省人天）的是做过的；只讲「提高效率释放人力」这类空话的是没主导过 |
| 加分项 | 主动讲自动化的局限和适用边界 |
| 减分项 | 说「自动化能发现所有 bug」或「领导要求就做」，认知不过关直接减分 |
