# 03｜UI 自动化适合覆盖什么？覆盖率目标怎么定？

> 开场先给选择标准再谈覆盖：UI 自动化覆盖两类——**高频执行的核心场景**（每次回归都要跑的主流程）和**人力难以完成的场景**。按用户使用频率和业务价值排序，从 P0 场景开始自动化，不是见页面就录。

## 回答思路

### 第一步：覆盖率目标讲两个口径

- **用例口径**：核心场景自动化覆盖率——比如 **P0 场景 100%、P1 场景过半**
- **代码口径**：UI 自动化不追求代码行覆盖，那没意义——**场景覆盖才是有效口径**，主动讲这个区别显得专业

### 第二步：给一个落地路径

第一版只做**冒烟集**，稳定运行三个月再扩回归集，覆盖率逐步爬坡——一上来定 80% 的目标必然烂尾。

### 第三步：讲不覆盖什么同样重要

频繁改版的页面、低频长尾场景、强视觉主观的检查——这些**明确排除并说明理由**。取舍清晰比大包大揽可信。

### 收尾：讲动态调整

每次线上问题回流评估要不要进自动化；覆盖率目标跟着业务阶段走——大促前收紧、平稳期扩面。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | UI 自动化是最容易过度投入又最容易烂尾的层。企业要看你有没有范围控制和目标管理能力，而不是写脚本的速度 |
| 过线标准 | 有选择标准（核心场景优先）+ 有覆盖率口径认知 |
| 区分度 | 讲「不覆盖什么」的清单和理由的是做过取舍的；说「尽量全覆盖」的是没被 UI 维护成本毒打过 |
| 加分项 | 讲冒烟先行、逐步爬坡的节奏，或用例口径和代码口径的区分 |
| 减分项 | 拿代码行覆盖率给 UI 自动化定目标，方向就错了 |
