# 04｜自动化用例和手工用例是什么关系？要把手工用例全部自动化吗？

> 开场先亮观点：**不是包含关系也不是替代关系，是两个不同的集合**——手工用例服务人的探索，自动化用例服务机器的回归，全集里只有交集部分适合自动化。

## 回答思路

### 第一步：给判定标准

| 适合自动化 | 不适合自动化 |
| --- | --- |
| 步骤固定可重复 | 需要人的主观判断（视觉体验、易用性） |
| 预期结果可精确断言 | 探索性步骤 |
| 执行频率高 | 一次性执行 |

用这个标准筛，**通常只有三四成手工用例值得自动化**。

### 第二步：讲设计差异

手工用例可以写「检查页面是否美观」，自动化用例必须**翻译成可断言的检查点**（元素存在、文案匹配、跳转正确）——这个翻译过程本身就是**用例再造**。直接把手工用例丢给录制回放工具，是烂尾的开始。

### 第三步：讲维护关系

两者共用一套用例库时用标签区分执行方式；手工用例变更要同步评审自动化用例——避免两套资产各自漂移。

### 收尾：给认知

自动化率不是越高越好，是「**值得自动化的部分自动化了多少**」。盲目追求自动化率数字，会逼着团队把不该自动化的也自动化，长期维护成本反噬。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 考察对自动化的定位认知。企业要的是能把自动化放对位置的人——不是见用例就想自动化的狂热者，也不是觉得自动化可有可无的保守派 |
| 过线标准 | 说得出适合/不适合自动化的判定特征 |
| 区分度 | 讲「翻译再造」「两套资产防漂移」的是真维护过双轨用例的；说「全部自动化才彻底」的是没想过成本 |
| 加分项 | 主动反对盲目追自动化率，有取舍立场 |
| 减分项 | 认为录制回放就能把手工用例变成自动化资产，暴露没踩过维护的坑 |
