# 02｜自动化测试的分层策略是什么？各层比例怎么定？

> 开场先画出**测试金字塔**：从下往上单元测试、接口测试、UI 测试——越往下越稳定、越快、越便宜；越往上越接近用户但越脆弱、越慢、越贵。分层本质是成本和收益的权衡。

## 回答思路

### 第一步：比例给参考值再说按项目调

经典比例大概**单元七成、接口两成、UI 一成**——但这是有单测文化的团队的结构；测试团队主导时通常是**接口为主、UI 只保主流程**。别把金字塔比例当教条，这是得分点。

### 第二步：讲每层的分工

- **单元层**：开发负责，测试推动覆盖率
- **接口层**：测试主投，性价比之王，业务逻辑校验的主战场
- **UI 层**：只覆盖核心业务主流程的冒烟和关键路径，不追求全覆盖

### 第三步：主动讲金字塔的变体认知

微服务时代有「**奖杯模型**」的说法——强调集成测试加厚、接口层变重。说明你跟进过方法论演进，而不是只会一张老图。

### 收尾：落到自己项目

讲你的项目里三层各多少条用例、跑多久、谁维护——落地现状比理论加分。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 分层认知决定自动化的成败——把资源全砸 UI 层的团队基本都会烂尾。企业通过这题判断你能不能做对技术决策 |
| 过线标准 | 金字塔三层讲清 + 说得出各层稳定性成本差异 |
| 区分度 | 讲「比例按团队实际调」「奖杯模型」的是有独立思考的；把七二一当标准答案背的是没落地过 |
| 加分项 | 明确说「UI 只保主流程」并给出理由（脆弱、慢、贵） |
| 减分项 | 认为自动化就是 UI 自动化，暴露对分层的理解为零 |
