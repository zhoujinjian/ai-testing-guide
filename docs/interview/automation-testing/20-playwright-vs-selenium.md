# 20｜Playwright 和 Selenium 有什么区别？新项目你会怎么选？

> 开场把差异按层讲——这题考的是技术视野和选型判断力，不是让你站队吹一个踩一个。

## 回答思路

### 第一步：架构差异

- **Playwright**：通过驱动和浏览器深度集成（默认用自带编译的浏览器，协议级通信）——不需要单独装驱动、不受浏览器版本匹配折磨
- **Selenium**：走 W3C 协议外挂驱动，环境问题多一层

### 第二步：能力对比

Playwright 的原生能力，在 Selenium 里都要自己封装或加插件：

- **原生自动等待**——动作前自动等元素可操作，从根上减少显式等待的样板代码
- **网络拦截和 mock**
- **多浏览器多上下文**——一个浏览器实例开多个隔离的 context，跑多账号场景快得多
- **trace viewer**——截图、网络、控制台一屏回放失败现场

### 第三步：生态上给公道话

Selenium 十几年生态：语言绑定全、社区资料海量、大厂存量框架多，存量系统迁移有成本。Playwright 生态新但增速快，微软主导迭代猛。**双方各讲一句公道话显得客观**。

### 第四步：选型给决策逻辑

- 新项目、团队允许引入新栈、追求开发效率和稳定性 → **Playwright**
- 存量 Selenium 框架运行良好、团队技能栈绑定、有大量二次封装资产 → **不折腾迁移**

选型服务于**团队现状**而不是技术新鲜度——这个立场是成熟工程师的标志。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 考察技术跟进度和选型判断力——2026 年的新项目大量在 Playwright 化，企业想知道你是守着 Selenium 十年不变，还是持续在评估新工具并能理性决策 |
| 过线标准 | 三方面差异（架构、能力、生态）讲出两点 |
| 区分度 | 讲「auto-wait 从根上治 flaky」「context 隔离多账号」的是真用过 Playwright 的；只说「Playwright 更新更快」的是看了营销文 |
| 加分项 | 存量不折腾、新项目才评估的务实选型观 |
| 减分项 | 无脑吹 Playwright 踩 Selenium，暴露没有真实选型经验 |
