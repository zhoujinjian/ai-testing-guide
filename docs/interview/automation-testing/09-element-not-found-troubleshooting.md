# 09｜Selenium 定位不到元素，你怎么排查？

> 开场给一套**有序的排查链**，不是想到哪查哪。

## 回答思路

### 五步排查链

| 步骤 | 查什么 | 要点 |
| --- | --- | --- |
| ① 定位器 | 选择器本身对不对 | 手动在开发者工具里跑一遍 selector，确认真能匹配到且唯一 |
| ② 时机 | 元素是异步加载的 | 脚本跑得比页面快——加显式等待重试。大部分「定位不到」其实是「**定位得太早**」，时机问题占这类故障的大头 |
| ③ 空间 | 元素在 iframe 里 | 必须 `switch_to.frame` 切进去才能找到，这是最经典的坑；新窗口新标签页要 `switch_to.window` 切换句柄 |
| ④ 状态 | 在 DOM 里但不可见/不可交互 | display none、被遮挡、disabled——existence 和 visibility 分开断言 |
| ⑤ 环境 | 本地能跑 CI 挂 | 无头和有头渲染差异、浏览器驱动版本不匹配、CI 加载了不同分支 |

### 收尾：给方法论总结

排查顺序就是「**定位器对不对 → 来得及吗 → 在哪个 frame → 什么状态 → 什么环境**」——把散点整理成检查清单的人，是真反复修过脚本的人。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 日常维护自动化最高频的工作场景。企业用这题直接考察排障经验和条理性——答得好说明天天在维护真实框架，答得散说明没修过几个坏脚本 |
| 过线标准 | 至少讲到时机和 iframe 两个高频原因 |
| 区分度 | 能给「排查链」这种结构化清单的是老手；罗列一堆可能没有顺序的是凭印象 |
| 加分项 | 讲无头渲染差异、CI 环境变量这类环境因素 |
| 减分项 | 第一个反应是「加 sleep 试试」——方向性错误 |
