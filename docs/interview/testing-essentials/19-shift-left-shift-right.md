# 19｜测试左移和测试右移是什么？你平时怎么落地？

> 开场先给一句话定义：**左移是把测试活动往开发前期移，在问题产生之前介入；右移是把质量保障延伸到线上，在问题暴露之后兜住**。各给定位，再分别展开。

## 回答思路

### 第一步：左移落地讲四件事

1. **需求评审阶段测试就位**：从可测性角度挑需求的毛病，模糊点和异常流程当场澄清
2. **用例先行**：开发没写完测试用例已评审完，提测即可执行
3. **技术评审和代码走查参与**：了解改动面，提前定回归范围
4. **静态检查和单测推动**：冒烟脚本提测前给开发自测用，把问题挡在提测之前

### 第二步：右移落地讲四件事

1. 上线验证清单加首日重点监控
2. **线上告警接入**：错误率、崩溃率、关键接口的成功率阈值告警
3. **灰度发布验证**：小流量先放观察再全量
4. **线上问题回流**：每个线上事故复盘后沉淀成用例和检查项，防同类问题复发

### 第三步：讲收益逻辑

左移降低修复成本——bug 越早发现越便宜；右移兜住漏网之鱼——质量不是测完就结束了。这说明你理解左右移背后是**成本和风险经济学**，不是赶时髦。

### 收尾：克制一点

左右移不是所有团队都做得全——能落地其中两三件并形成习惯就有效果。关键是测试的角色从「版本内执行」变成「**全生命周期质量参与**」。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 考察质量视野：你的质量观是停留在「接需求跑用例」，还是覆盖研发生命周期。有左右移意识的测试能帮团队把事故消灭在前面，这是资深和初级的分界 |
| 过线标准 | 定义准确 + 每侧至少两个落地动作 |
| 区分度 | 讲得出自己团队真实落地动作（哪怕只有一两件）的是真参与过的；只背名词的，追问一句怎么落地就空了 |
| 加分项 | 「线上问题回流成用例」这条闭环，或者一个左移拦住大问题的真实案例 |
| 减分项 | 把左移说成「早点开始测」——概念性错误，暴露只是听过名词 |
