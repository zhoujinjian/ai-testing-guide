# 12｜接口测试怎么做？没有接口文档怎么测？

> 开场先给接口测试的价值定位：**绕过 UI 直接测服务层**——比 UI 稳定、跑得快、覆盖成本低，还容易做进 CI。这段开场说明你理解为什么测接口，而不是只会用 Postman。

## 回答思路

### 第一步：单接口测试，断言三层

1. **状态码**对不对
2. **响应体**字段和值对不对
3. **数据库有没有正确落库**——第三层是区分度，很多人漏了数据校验这层

### 第二步：参数验证

必填校验、参数类型、长度边界、特殊字符、必传漏传、错误枚举值——等价类边界值在接口上照用。

### 第三步：场景层展开

- **业务链路**：注册登录下单串联，上一个接口的返回喂下一个
- **异常场景**：重复提交的幂等性、并发下的数据一致性、鉴权 token 过期
- **依赖 mock**：下游服务挂了被测接口怎么表现

### 第四步：没有接口文档三条路

1. **抓包逆向**：UI 上操作一遍把接口全抓出来，请求响应就是文档
2. **找开发要 swagger 或代码里的接口定义**——代码即真相
3. **用例沉淀反哺文档**：测完把整理的接口清单发给开发确认，长期把文档建起来

### 收尾：工具带一句

Postman 做调试、pytest 加 requests 做自动化、JMeter 做接口性能，各司其职。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 接口测试是功能测试进阶的标配能力，也是自动化投入产出比最高的层。企业通过这题判断你能不能在服务层干活，还是只会黑盒点 UI |
| 过线标准 | 断言三层讲全 + 参数验证有方法论 |
| 区分度 | 主动讲数据库落库校验、幂等性、并发一致性的，是真做过接口测试的；只讲「用 Postman 发请求看返回」的是刚入门 |
| 加分项 | 抓包逆向接口并反哺文档的经历，或者接口自动化进了 CI 的实践 |
| 减分项 | 说没有文档就测不了——思维僵化直接扣分 |
