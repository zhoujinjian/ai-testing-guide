# 01｜拿到一个新项目，你会怎么开展测试？

> 开场先反问再作答：拿到的是**新项目还是新版本**、有没有需求文档、时间点是什么——这一句反问本身就是得分点，面试官在看你有没有「先弄清任务再动手」的习惯。

## 回答思路

### 第一步：按阶段展开

| 阶段 | 做什么 |
| --- | --- |
| **需求阶段** | 参与需求评审，把需求读懂吃透、澄清模糊点，这个阶段就开始产出测试点 |
| **计划阶段** | 明确测试范围、测试策略、资源分工、时间节点和风险预案 |
| **设计阶段** | 拆解功能点、设计用例、组织用例评审 |
| **执行阶段** | 环境准备、冒烟准入、正式执行、提交和跟踪 bug |
| **收尾阶段** | 回归测试、输出测试报告、上线验证 |

### 第二步：讲清楚两个门

- **准入**：冒烟不通过打回开发，不带病测试
- **准出**：缺陷收敛、遗留问题评审确认后才允许上线

### 第三步：提风险意识

中途回归范围怎么定、时间被压缩怎么裁剪（保核心主流程、砍边缘场景）——这些话能让面试官感觉你是**扛过项目的人**。

### 收尾：点一句持续沉淀

用例进用例库、线上问题回流成用例，越测越省力。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 考察新人能不能直接接活的第一个问题。回答里有没有阶段感、门禁意识，直接判断你是「跑用例的」还是「管质量的」 |
| 过线标准 | 阶段完整（需求到上线闭环）+ 有准入准出概念 |
| 区分度 | 初级背流程名词；资深会讲每个阶段的产出物、会讲时间不够时怎么裁剪、会主动提风险 |
| 加分项 | 说出「需求评审阶段测试就该介入」——测试左移意识直接加分 |
| 减分项 | 只会说「拿到需求写用例、执行用例提 bug」，没有头尾，暴露没独立负责过项目 |
