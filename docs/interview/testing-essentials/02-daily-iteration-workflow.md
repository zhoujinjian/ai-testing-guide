# 02｜描述一下你的测试流程，一个版本迭代里你具体做什么？

> 开场先和 01 划清边界：01 是从零建体系，这题讲**日常迭代的个人动作**，回答要具体到产出物。

## 回答思路

### 按时间线讲

| 节点 | 具体动作 |
| --- | --- |
| **迭代开始** | 参加需求评审和**需求反讲**，重点听边界条件和异常流程，当场提出测试视角的疑问 |
| **开发阶段** | 用例设计和评审；同步开发做接口联调用例准备，有条件提前介入接口测试 |
| **提测前** | 确认环境、数据、部署就绪 |
| **提测当天** | 先跑冒烟，通过才正式接 |
| **执行阶段** | 每天同步执行进度和 bug 状态，跟踪修复并做回归 |
| **版本后期** | 二轮三轮回归，核心场景必覆盖 |
| **上线前** | 输出测试报告，参与发布评审 |
| **上线后** | 线上验证加首日监控 |

### 讲一个自己的真实节奏感

比如一个两周迭代自己大概维护多少条用例、提多少 bug、花多少时间在回归上——**数字一出来，真实感就出来了**。

### 收尾：和 01 呼应

流程不是死的：敏捷迭代里测试和开发并行，关键节点不省就行。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 判断你是真做过版本还是只在简历上写过。流程里有没有「需求反讲、冒烟准入、回归、报告」这些具体动作，做过的人脱口而出，没做过的人卡壳 |
| 过线标准 | 能完整讲一遍迭代周期内测试的动作闭环 |
| 区分度 | 讲得出「需求反讲」「提测门禁」「上线验证」这类细节的，是真在敏捷团队待过的；只会「写用例、执行、提 bug」三段式的，是培训班答案 |
| 加分项 | 提到迭代内自动化回归省人力、提到每天和开发的进度同步机制 |
| 减分项 | 流程和上一个问题答得一模一样，暴露对「体系」和「日常」没有层次感 |
