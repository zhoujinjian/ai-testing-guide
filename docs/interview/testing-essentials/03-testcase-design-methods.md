# 03｜测试用例设计方法有哪些？分别在什么场景下用？

> 开场先报方法名再讲使用场景：经典六种一口气说完再逐个展开，显得**心里有清单**。

## 回答思路

### 第一步：六种方法各配一句适用判断

| 方法 | 适用场景 |
| --- | --- |
| **等价类** | 输入域可分类时减少冗余用例 |
| **边界值** | 有取值范围的字段必用——bug 爱藏在边界上（0、1、上限、上限加一） |
| **判定表** | 多个条件组合影响结果时用，把条件和动作列成表防遗漏 |
| **场景法** | 业务流程长的功能用，基本流加备选流 |
| **正交法** | 组合因子太多用正交表科学抽样，兼容性矩阵常用 |
| **错误推测法** | 凭经验直捣黄龙，比如复制粘贴带空格的输入、特殊字符 |

### 第二步：举一个综合例子收尾

比如注册功能：用户名长度用**边界值**、类型合法非法用**等价类**、密码强度规则组合用**判定表**、整体注册成功失败流程用**场景法**。

### 收尾：主动补一句用例质量怎么看

覆盖需求、颗粒度合适、正反例兼顾、可执行可回归——**方法只是手段，覆盖完整才是目的**。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 测试岗的看家本领，八股里最不能错的一题——答不出等于基本功没过关，后面的问题基本不用问了 |
| 过线标准 | 六种方法至少说出四种并能配使用场景 |
| 区分度 | 能讲「什么时候用什么」的是做过用例设计的；只会背名词定义的，追问一句「边界值在你项目里举个实际例子」就露底 |
| 加分项 | 能讲错误推测法的来源（经验和历史 bug 库沉淀），说明有积累意识 |
| 减分项 | 把方法当孤立知识点背，讲不出组合使用，暴露没有真实设计过用例 |
