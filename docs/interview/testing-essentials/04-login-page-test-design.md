# 04｜给你一个登录页面，你怎么设计测试用例？

> 开场先给答题框架再展开：**功能、界面、性能、安全、兼容性、易用性、异常场景**——七个维度报完，面试官就知道你脑子里的网是完整的。这题拼的就是维度覆盖，不全丢分。

## 回答思路

### 第一步：功能是主体

- 正确组合、错误组合（账号错、密码错、都错）
- 空值、长度边界
- 验证码（对错、过期、刷新）、记住密码、忘记密码链路
- 多端登录互踢、登录成功跳转

### 第二步：安全是区分度所在

- 密码是否**加密传输**（明文抓包一验便知）
- 错误次数锁定，防暴力破解
- SQL 注入和 XSS 试探、验证码可否绕过
- session 过期处理、返回按钮回退是否还能操作

### 第三步：异常和兼容

- 断网、弱网、超时的提示
- 不同浏览器、分辨率、机型
- 密码输错后的提示是否泄露「账号不存在」这类信息

### 第四步：讲完主动总结方法论

这题的答法可以迁移到任何「怎么测一个 XX」场景题——**先定维度框架再逐维度展开**，电梯、水杯、微信发红包全是这一个套路。

### 收尾：控制节奏

别真列三十条。讲两三分钟给出结构感和代表性用例就够了，然后说「完整的用例我会在用例管理工具里细化」。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 出现率最高的场景题没有之一，考察测试思维的完整性和结构化表达——企业要看你拿到一个东西能不能自己搭出测试框架，而不是等人喂用例 |
| 过线标准 | 功能完整 + 至少覆盖性能、安全、兼容中两项 |
| 区分度 | 能主动讲安全项（加密传输、暴力破解、错误提示信息泄露）的是有实战经验的；只罗列功能点的在校生也能答出六成 |
| 加分项 | 提「错误提示不区分账号不存在还是密码错误，防账号撞库」——一句话证明你有安全攻防意识 |
| 减分项 | 想到哪说到哪没有框架，面试官心里给你打的分是想到多少给多少 |
