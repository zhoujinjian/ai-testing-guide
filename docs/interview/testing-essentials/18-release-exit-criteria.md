# 18｜怎么判断一个版本测完了、可以上线了？

> 开场先破题：**「用例都跑完」不等于「测完了」**——判断的依据是风险收敛，而不是执行完毕。这个认知先立住。

## 回答思路

### 第一步：给一套可落地的出口标准

- **需求覆盖率**：需求点全部有用例覆盖且执行完
- **用例执行率**：计划用例执行完毕，跳过的要说明原因
- **缺陷收敛**：致命和严重级 bug 修复率 100% 且回归通过；一般级遗留要逐条评审、有规避方案、相关负责人确认接受
- **关键路径**：核心业务主流程冒烟全绿
- **产出物**：测试报告齐备，风险清单明示

### 第二步：讲「遗留 bug 评审」这个关键动作

遗留问题不是测试默许就完事——要拉着产品和项目负责人**逐条过**。接受风险的责任在项目组不在测试单方，留痕到邮件或文档。

### 第三步：讲边界情况的判断力

时间被砍时的裁剪逻辑：保主流程保核心、边缘场景降级为上线后观察加监控——**主动暴露裁剪了什么**，而不是假装都测了。

### 收尾：呼应 10 题

出口标准是**版本开始时就该定好的**，不是结尾临时凑的——开始时定了标准，结束时才有对照。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 测试工程师从执行者走向负责人的分水岭题。企业要的是能对上线质量签字的人：敢定标准、能扛质疑、会留痕 |
| 过线标准 | 出口标准成体系 + 遗留 bug 要评审确认 |
| 区分度 | 讲「风险收敛而不是执行完毕」「标准在版本开始时定」的是有质量决策经验的；只会说「用例跑完没 bug」的是执行者视角 |
| 加分项 | 主动讲裁剪时的透明化，暴露裁剪内容给项目组——这种坦荡的质量姿态很打动面试官 |
| 减分项 | 「领导说上就上」或「开发说没问题就上」，没有质量立场，这题直接出局 |
