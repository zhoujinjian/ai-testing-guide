# 07｜怎么判断一个 bug 是前端的还是后端的？

> 开场给方法论：前后端的**分界线就是接口**——抓包看接口的请求和响应，定位就完成了一大半。

## 回答思路

### 第一步：抓包分析讲成一套四分支判定逻辑

| 现象 | 判定 |
| --- | --- |
| 请求没发出去 | **前端问题**（按钮事件没绑定、JS 报错） |
| 请求发出但参数错 | 查数据来源：表单取值错是前端；前端传对了后端理解错是后端 |
| 请求正常但响应数据错 | **后端问题** |
| 响应数据对但页面显示错 | **前端渲染问题** |

这套四分支逻辑是本题的骨架，讲顺了面试官就知道你天天抓包。

### 第二步：补充另外两个手段

- **看后端日志**：请求有没有到服务端、有没有异常堆栈，直接定位后端代码问题
- **查数据库**：接口返回的数据和落库数据对不上，能进一步判断是业务逻辑错还是查询组装错

### 第三步：带上工具名

浏览器 **F12**（Network、Console 看 JS 报错）、**Fiddler / Charles** 抓包、服务器上 grep 日志——工具链报得越具体越可信。

### 收尾：补边界

移动端 App、小程序、H5 混合页面还有一层——先分清是**原生页面还是 Web 容器**，再套上面的逻辑，别把客户端的问题误判给服务端。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 考的是测试的技术深度能不能超越「点点点」。会定位的测试提的单子开发愿意接；不会定位的，测试和开发之间永远在扯皮 |
| 过线标准 | 讲得出抓包四分支判定逻辑 |
| 区分度 | 四分支讲成因果链的是真排查过的；只会说「看日志问开发」的是没独立定位过 |
| 加分项 | 主动提 F12 Console 看 JS 报错、提查数据库三方印证，工具箱越全越加分 |
| 减分项 | 说「让开发自己看」——测试价值为零的回答，直接暴露定位能力缺失 |
