# 15｜AI 工具在团队推不动，怎么破局？

> 开场先**诊断推不动的真实原因**，不是统一对策——先诊断再开方，是本题的结构分。

## 回答思路

### 第一步：四种病因

| 病因 | 表现 |
| --- | --- |
| **不会用** | 没掌握方法，生成质量差就放弃了 |
| **不敢用** | 怕生成内容背锅、怕被 AI 替代 |
| **没好处** | 用不用一个样，考核里不体现 |
| **没时间** | 忙着赶版本没空学新东西 |

### 第二步：对应的破局打法

1. **树立标杆场景**：选一个痛点最痛的环节做出肉眼可见的提效案例（用例生成从四小时到一个半小时），让数据说话
2. **降低门槛**：把 prompt 和流程封装好，同事复制就能用——别要求人人都会 prompt 工程
3. **融入现有流程**：AI 环节嵌进用例评审和 CI 流程成为**默认动作**，而不是额外动作
4. **领导示范加轻度考核**：团队 AI 使用纳入过程观察，不搞强 KPI 防止形式主义应付

### 第三步：讲推广的节奏

先找两三个愿试的人做**种子用户**，跑出效果扩到小组，最后全团队。**先易后难**（文档类先推、用例类次之、脚本类最后）——节奏感和「冒烟先行」的思路同构，都是先小闭环再放大。

### 第四步：讲应对阻力的话术成熟度

- 对「怕被替代」：**AI 替代的是重复劳动不是判断力，早用的人替代晚用的人**
- 对「生成质量差」：是方法问题（上下文没喂够）——用案例现场演示改喂法的效果。**说服靠演示不靠辩论**

### 收尾：给度量收口

推广效果看**采纳率曲线**（周活跃、覆盖人数、场景渗透）——停滞了回访找卡点。推广本身也是个迭代产品。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 采纳率是 AI 项目失败的头号原因——有推广能力的人才能让投入变现，这题考察组织推动力，是往测开负责人走的必答题 |
| 过线标准 | 先诊断病因再分策 + 标杆场景打法 |
| 区分度 | 讲种子用户节奏、讲应对阻力话术的是真推过的；只会「多培训几次」的是没推过的 |
| 加分项 | 采纳率曲线的运营度量 |
| 减分项 | 把推不动全归咎于「同事不思进取」，没有自我方法论的反思 |
