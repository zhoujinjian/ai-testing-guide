# 09｜作为测试负责人，你怎么把住版本的发布质量关？

> 开场先讲「把关」的正确理解：**不是测试负责人个人拍板放行**（那是把体系问题个人化，人肉门禁不可持续），而是建设「**质量门禁体系**」让把关机制化。**管理者的角色是「建门」而不是「守门」。**

## 回答思路

### 第一步：门禁的分层设计（四道门）

| 门 | 内容 |
| --- | --- |
| **准入门** | 提测标准——冒烟不过打回 |
| **过程门** | 执行率、缺陷收敛趋势的中间检查点 |
| **准出门** | 出口标准清单——致命严重清零、遗留评审、报告齐备（合集二 18 题的体系在团队级的落地） |
| **发布门** | 发布评审会测试意见的正式表达 |

### 第二步：讲有争议时的决策机制（资深管理者的标志）

- **红线内**（资损、数据错误类）：测试**一票否决**
- **红线外**（体验类、边缘场景类）：提交**质量委员会集体决策**（产品、开发、测试的联合评审）

分级授权——**既守底线，又不让测试成为单点瓶颈**。

### 第三步：讲风险沟通的表达方式

- **结论给数据**：遗留缺陷清单 + 影响评估 + 观察预案——不是「我感觉不稳」
- **立场要坚定、表达要专业**：反对时给证据和替代方案（「这个情况下建议延期两天，或灰度百分之十」），不是情绪化地拦

**把关的专业性体现在说服力。**

### 收尾：讲责任与权力的对等认知

测试负责人对质量结论负责，对应的要有门禁的**制定权**和否决的**支撑力**（管理层的授权）——有权无责或有责无权都会把把关做虚。**入职时就该和上级把这个边界谈清楚。**

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 企业通过这题看你是「体系型守门人」还是「人肉审批章」——前者可规模化可传承，后者离了你就不行 |
| 过线标准 | 建门不守门的定位 + 四道门 + 分级授权机制 |
| 区分度 | 讲质量委员会集体决策、讲结论给数据的表达方式的是有把关实战的 |
| 加分项 | 责任权力对等的边界意识 |
| 减分项 | 「所有上线都归我签字」揽权式回答，或「听领导的」弃权式回答——两个极端都不专业 |
