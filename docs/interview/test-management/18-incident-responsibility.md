# 18｜线上出了事故，测试团队要不要背责任？

> 开场先亮立场框架：**责任要分，不是要么全背要么全甩**——分类分责的框架比笼统态度专业十倍。

## 回答思路

### 第一步：按「问题在哪个环节漏出」分责

| 漏出环节 | 责任 |
| --- | --- |
| 需求阶段埋的雷（需求缺陷） | 产品担主责 |
| 开发实现的问题且测试合理覆盖下漏出（概率性或环境差异） | 开发担主责，测试担漏检的次责 |
| 测试覆盖缺失（该测没测） | 测试担主责 |
| 流程时间压缩导致的（决策层选择的风险） | 决策方担责 |

### 第二步：讲「合理漏测」的辩护边界

- 测试是**抽样不是穷尽**（合集二的认知前提）
- 概率性场景的逃逸在统计意义上必然发生——**逃逸率不为零是科学规律**
- 环境差异导致的漏网——要拿「曾推动环境一致性」的记录证明测试尽了责

**但辩护要有证据**（当时的测试报告、风险评估的记录）——没记录的辩护是耍嘴皮。

### 第三步：讲责任的主动性姿态

- 测试环节的问题**主动担**——担责后给改进方案（担当加改进的组合是加分项）
- 不是测试的问题**建设性指出**——用复盘的分析链条说清，不甩锅但也不背锅
- **团队的担当文化**：管理者对外担总责、对内查真因——把团队护住，把问题改掉。这个姿态赢的是长期信任

### 第四步：讲机制化的预防「被动背锅」

- **测试范围的书面确认**（砍范围时的风险确认邮件——合集二 10 题的机制）
- **质量数据的留痕**（测试报告和风险评估的存档）
- **边界的入职共识**（和上级事先对齐「测试的责任边界是什么」）

**白纸黑字的机制是事后扯皮的终结者。**

### 收尾：给一个认知的收口

**追责的目的不是惩罚，是改进**——惩罚导向的追责会催生掩盖和保守（没人敢测新东西、没人敢报风险）。健康的组织问「**系统哪里漏了**」而不是「谁的错」——测试经理在这场讨论里既是参与者，也是文化塑造者。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 背全锅团队士气崩、全甩锅协作关系崩——考察分责的框架、担责的姿态、防扯皮的机制三层能力 |
| 过线标准 | 分责框架 + 担责姿态 + 机制化预防 |
| 区分度 | 讲「辩护要有证据留痕」、讲「管理者对外担总责对内查真因」的是有担当智慧的 |
| 加分项 | 「追责为了改进不为惩罚」的文化收口 |
| 减分项 | 「测试是最后一道关都怪测试」的无限责任论（自己给自己挖坑）或「我们测的都过了怪开发」的甩锅论（协作自杀）——都是不专业 |
