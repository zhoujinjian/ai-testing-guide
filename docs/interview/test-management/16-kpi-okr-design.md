# 16｜测试团队的 KPI（OKR）怎么定？怎么衡量团队绩效？

> 开场先讲结果和过程的**组合结构**——纯结果指标（逃逸率）团队不可控因素多会挫伤；纯过程指标（用例数）会催生数字游戏。

## 回答思路

### 第一步：三层组合结构（本题地基）

**结果指标定方向 + 过程指标给路径 + 能力建设看长期**——三层组合各占一定权重。

### 第二步：给一个具体的指标参照

| 层 | 指标 |
| --- | --- |
| **结果层** | 缺陷逃逸率（团队级）、线上故障数、版本按期率 |
| **过程层** | 自动化覆盖率、需求测试参与率、缺陷修复验证时长 |
| **能力层** | 平台工具的建设进度、人员的认证和成长 |

三层各挑两三个——**指标不在多，在准。**

### 第三步：讲指标设计的防博弈（合集七 11 题的团队级应用）

- 逃逸率的口径要**防刷分母**（有效缺陷的评审确认）
- **bug 数不进 KPI**（防凑数和防对立）
- 自动化覆盖率和有效性**成对看**（防假覆盖）

每个指标都想一遍「**如果团队只优化这个数字会发生什么**」——答案是坏的就要配护栏或换指标。

### 第四步：讲 OKR 和 KPI 的选择逻辑（不赶时髦）

- 成熟稳定业务用 **KPI**（守成型，指标可预测）
- 创新探索期用 **OKR**（进攻型，鼓励挑战失败容忍）
- 测试团队常见的是**混合**：质量底线 KPI 化、效率提升 OKR 化

### 收尾：讲考核的落地原则

**团队级考核为主**（质量是团队产物——个人级强行拆分会逼出局部优化）；考核结果和发展反馈**分开**（谈钱和谈成长混在一起两边都谈不好）；分布的公正性（强制排名小团队慎用）。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 指挥棒设计错误，团队行为全部变形——考察指标设计功力和防博弈意识，这是把合集七的度量知识用到自己团队的能力检验 |
| 过线标准 | 三层组合结构 + 防博弈设计 |
| 区分度 | 讲「优化这个数字会发生什么」的自检法、讲 KPI 和 OKR 的选择逻辑的是体系级思考 |
| 加分项 | 团队级考核为主的原因阐述 |
| 减分项 | KPI 就是 bug 数和用例数（测试管理史上最大的两个坑），或「我们不讲 KPI 讲奉献」——两个极端都不合格 |
