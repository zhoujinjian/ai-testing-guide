# 01｜测试经理（测试组长）的职责是什么？和高级测试工程师有什么区别？

> 开场先给职责的**四象限**——管理岗面试的第一题定基调。

## 回答思路

### 第一步：四象限职责

| 象限 | 职责 |
| --- | --- |
| **对事** | 测试策略制定和质量标准把关（测什么、测到什么程度、放不放过） |
| **对人** | 团队建设（招聘、培养、绩效、激励） |
| **对流程** | 测试体系建设和改进（流程规范、工具落地、左移右移的推进） |
| **对上对外** | 风险汇报和跨部门协同 |

### 第二步：讲和高级工程师的本质区别（产出物变了）

- 高级工程师的产出是**测试执行和质量发现**（用例、bug、测试结论）
- 管理者的产出是**通过团队拿到的结果**（团队的质量保障能力、人才的成长、体系的进步）

一句话：「**从自己干变成让团队干得好**」——价值杠杆从个人技能变成组织能力。

### 第三步：讲职责的权重分配给个参照

技术参与（方案评审、疑难攻关）三四成、管理动作（一对一、绩效、规划）三四成、对外协同两三成——**完全脱离技术的管理者会失去判断力，完全陷在技术里的管理者会缺位**。

### 第四步：讲一个常见误区

管理者**不是「最忙的那个人」**——事事亲力亲为的管理者培养不出团队还把自己累死。管理者的忙应该忙在「**别人替代不了的事**」上（定方向、建机制、培养人）。**团队越强，管理者越应该「闲」**——这个反直觉的认知是管理成熟度的标志。

### 收尾：给角色演进的意识

组长（带人干活）、经理（建体系管质量）、总监（定战略管组织）每层职责重心不同——**知道自己应聘的层级**，讲出该层的关键词。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 「技术最好的人提管理者」的惯性思维（继续自己干）是管理失败的头号原因——企业先用这题验转型成没成 |
| 过线标准 | 四象限职责 + 和工程师的本质区别 |
| 区分度 | 讲产出物变化、讲权重配比、讲「管理者不能最忙」的是完成认知转型的 |
| 加分项 | 按应聘层级调整答案的意识 |
| 减分项 | 职责就是「分配任务、催进度」，把管理干成了调度员 |
