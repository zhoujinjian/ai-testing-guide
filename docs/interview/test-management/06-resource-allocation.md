# 06｜多个项目并行，测试人力怎么调配？

> 开场先讲**底账意识**：人力盘点的表（每个人在什么项目、投入多少、什么时候释放）——**没有这张表的调配全是拍脑袋**。

## 回答思路

### 第一步：调配的优先级框架

按**业务重要性**（核心营收项目优先）+ **紧急度**（交付时间硬的优先）+ **风险**（新项目风险高要多投入）综合排序——重要紧急的保、重要不紧急的排计划、紧急不重要的协调（和产品谈延期）、不重要不紧急的砍。

### 第二步：讲弹性手段的清单（四类组合用）

| 手段 | 要点 |
| --- | --- |
| **内部调剂** | 项目间隙的人员借调——但要讲清楚**回归时间点**，防止「借了不还」 |
| **技能冗余** | 关键技能至少两人会，调配才有空间（04 题的备份原则复用） |
| **外部补充** | 外包处理标准化执行、内部专注核心 |
| **需求侧调节** | 和产品谈判**砍范围保时间**——测试压力传导回需求端 |

### 第三步：讲预防性的机制

- **人力预警**：按排期提前一个月看资源缺口——早协调比临时抓人从容十倍
- **需求波动的缓冲**：固定比例的机动人力应对插队需求
- **和多项目管理的接口**：项目排期变化及时同步测试

**firefighting 的多数原因是预警缺失。**

### 收尾：讲调配的透明和公平

调配逻辑对团队公开（为什么调他去那，而不是偏心）、被频繁调动的人要有补偿（调薪评优的倾斜）——**黑箱调配是团队怨气的头号来源。**

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 多项目并行是测试团队的常态（人力永远比需求少）——「救火队长式管理者」和「体系型管理者」的分界题 |
| 过线标准 | 优先级框架 + 四类弹性手段 |
| 区分度 | 讲人力预警机制、讲借调要讲回归时间、讲调配透明的是真管过多项目团队的 |
| 加分项 | 压力传导回需求端（和产品谈砍范围）的 upstream 思维 |
| 减分项 | 「让大家加加班克服一下」——用透支团队解决结构问题，既无方法也不可持续 |
