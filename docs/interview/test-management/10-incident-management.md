# 10｜线上出了事故，作为测试经理你怎么处理？

> 开场先分**两个时段**：事故处理和事故复盘——混在一起做，不好两件事都做砸。

## 回答思路

### 第一步：事故进行时（先把火灭了）

**止损第一**——协助定位和验证修复方案，恢复业务优先于追责（复盘里没有人机对立的情绪）；测试的动作：快速验证修复版本、评估影响范围、盯回归。

### 第二步：复盘的结构化流程（四步讲全）

1. **时间线重建**：从故障发生到恢复的完整事件链，每一步谁做了什么
2. **根因分析**：**五问法**连问为什么——直接原因之外找系统原因（为什么漏测、为什么监控没报、为什么流程没拦住）
3. **改进项定责定时**：每条有 owner 和 deadline，进跟踪表
4. **复盘会**：对事不对人的氛围——目标是改进不是批斗

### 第三步：讲测试团队的责任分析框架（测试经理最痛的部分）

| 归因 | 处理 |
| --- | --- |
| 用例覆盖缺失 | 测试设计的锅——补用例 |
| 环境差异 | 测试环境复现不了的线上场景——推环境建设 |
| 流程问题 | 时间压缩导致没测到——推流程保障 |
| 概率性场景 | 合理范围内的漏网——量化评估后接受 |

**分类后该认的认、该辩的辩**——全盘认领和全盘甩锅都不专业。

### 第四步：讲向管理层汇报的分寸

事实完整（时间线、影响、根因、责任）、态度担当（是测试环节的问题坦诚认，是系统问题建设性指出）、方案具体（改进项和防复发机制）——**汇报的质量决定管理层对测试团队的长期信任。**

### 收尾：讲事故的价值转化

事故是质量体系最贵的学费——每个事故沉淀（回归用例、监控告警、流程规则、预案）。**「同类事故不犯第二次」是事故处理的金标准。**

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 事故见真章——考察临场的章法、复盘的专业度、责任的担当度三个维度，答得好坏的差距是「经历过并且成长了」和「没经历过或没复盘过」的差距 |
| 过线标准 | 止损和复盘分时段 + 结构化复盘流程 + 责任归因框架 |
| 区分度 | 讲五问法、讲分类认责、讲「不犯第二次」金标准的是真主持过复盘的 |
| 加分项 | 向管理层汇报的分寸感 |
| 减分项 | 复盘会开成批斗会（对人不对事）或开成免责会（全员没责任）——两个都说明不会复盘 |
