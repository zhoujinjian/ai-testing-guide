# 05｜怎么招聘测试工程师？你面试的时候考察什么？

> 开场先讲**画像是招聘的起点**——很多人招聘失败是因为「用一套题面所有人」，招来同质化的团队。

## 回答思路

### 第一步：按要补的岗位定画像

执行型看**细心和责任心**、测开型看**代码和工程能力**、资深型看**体系和方法论**——不同的岗不同的题。

### 第二步：面试考察框架（四块）

| 模块 | 考察 |
| --- | --- |
| **基础功** | 用例设计、流程认知（合集二的那些题就是筛子） |
| **技术深度** | 定位能力、SQL、自动化——按岗位深浅调整 |
| **实战验证** | 项目经历深挖：「你具体负责什么、最难的问题怎么解决的」，细节追问辨真伪 |
| **软素质** | 沟通表达、学习意愿、稳定性 |

**面试是有框架的评估，不是聊天。**

### 第三步：讲几个实战的鉴别手法

- **STAR 追问**：说做过接口自动化，那接口的断言分几层、数据怎么清理——**两层追问还在的才是真做过**
- **场景题观察思路**：给一个「怎么测登录页」，看结构化思维（合集二 04 题就是现场版）
- **反直觉题看心态**：「测试发现不了所有 bug，你怎么看」——看质量观

手法具体，说明真的面过很多人。

### 第四步：讲招聘决策的三条原则（招错过人的痛换来的）

1. **宁缺毋滥**（错的人进团队的纠错成本是招聘等待的十倍）
2. **潜力优先于现状**（学习能力强的人两年后远超熟手）
3. **价值观一票否决**（技术再好，甩锅心态和不诚信直接过）

### 收尾：讲入职后的衔接（招聘的闭环）

试用期目标明确（第一个月干什么、怎么算合格）、**导师制**（新人有人带）、定期反馈（周度沟通，不行早发现早处理）——**融入失败等于白招。**

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 招错人的代价企业最清楚——隐藏目的：你讲自己的面试框架时，暴露的是你对「什么是好的测试工程师」的理解深度，**你的标准就是团队的天花板** |
| 过线标准 | 分岗位画像 + 四块考察框架 |
| 区分度 | 有具体鉴别手法（追问辨真伪、场景题）的是面过很多的；「聊聊项目看看人品」是没体系的面法 |
| 加分项 | 宁缺毋滥和价值观一票否决的原则性 |
| 减分项 | 只看「会不会自动化工具」，把招聘等同于技能清单核对 |
