# 16｜测试计划、测试方案、测试报告，怎么写才不流于形式？

> 开场先讲三份文档各自回答什么问题：**测试计划**回答「怎么安排」（范围、资源、进度、风险，给项目组看的管理文档）、**测试方案**回答「怎么测」（策略、重点、环境、工具，给测试团队看的技术文档）、**测试报告**回答「测得怎么样」（结果、遗留、结论，给决策看的质量文档）。三问分清，文档的定位就立住了——**大量文档流于形式是因为定位错了**（把计划写成方案、把报告写成流水账）。

## 回答思路

### 第一步：讲不流于形式的核心标准

**每份文档要有人用它做决策**——计划被用来排期调资源、方案被新同事用来上手、报告被用来决定发不发布。没人用的文档是应付检查的作业，**写之前先问「谁看、他看完要做什么」**。

### 第二步：各文档的关键内容给干货

- **计划**：范围和不在范围（**明确不测什么比测什么更重要**，边界是谈判的依据）、风险和预案（提前想好时间被压缩怎么办）、资源依赖（人和环境的明确需求）
- **方案**：测试策略的取舍（重点攻哪里、为什么）、与既往的差异（这次和上次比策略变了什么）
- **报告**：**结论先行**（能不能上，先给结论再给数据）、遗留风险清单（带影响评估和观察建议）

### 第三步：讲轻量化的实践

- **文档跟着团队规模走**：三五人的小团队，计划一页、方案在用例库里、报告一封邮件——仪式感让位于信息传递
- **模板沉淀**：团队统一模板降低写文档成本，文档的可持续性靠低成本

### 收尾：讲文档的时效性

文档是**活的管理工具**（计划随项目调整要更新、报告在关键节点即时输出）——写完即过期的文档不如不写。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 文档能力是测试的职场基本功也是面试的实际考点（入职就要写），企业烦的是「八股文档工程师」（格式漂亮信息空洞）——这题筛的是「文档为决策服务」的实用主义者 |
| 过线标准 | 三文档的定位分清 + 有人用它做决策的标准 |
| 区分度 | 讲「范围里写不测什么」、讲报告结论先行、讲轻量化适配团队规模的是真写过多份的 |
| 加分项 | 模板沉淀降成本的意识 |
| 减分项 | 文档就是「按模板填满」，说不出每份文档给谁看、看完干什么 |
