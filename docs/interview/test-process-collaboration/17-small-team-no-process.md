# 17｜加入一个小团队（初创公司），没有成熟流程，你怎么开展工作？

> 开场先讲心态和判断：小团队没有流程**不是缺陷是阶段**（早期求生存，流程重了反而是包袱），你的任务不是「照搬大厂流程」而是「**按当前痛点搭最小够用的流程**」。这个判断先立住——答「把大厂流程引进来」是错的，答「没有流程也挺好」也是错的。

## 回答思路

### 第一步：讲最小流程的建设

- **从止血点起步**：团队最痛的是什么——提测质量差就先立冒烟门禁、环境乱就先立环境公约、bug 管理乱就先统一缺陷流转，一个痛点一个动作
- **轻量优先**：规则写进群公告和 checklist，不搞平台和审批流——成本高到团队不愿意遵守的规则等于没有
- **随规模演进**：人到十几人了再上用例管理工具和流程规范，流程跟着人数和业务复杂度长

### 第二步：讲一人测试的特殊处境

- **你是唯一测试时，职责是「质量的关键人」不是「质量的所有人」**——推动开发自测、把测试方法教给全团队，质量共建在小团队更可行（人少反而容易共识）
- **优先级即战略**：测不完是常态，核心链路的守护和风险的显性化是你每天最重要的判断——出口标准在一人团队就是你的日常决策

### 第三步：讲快速立足的动作

- **前两周摸清业务和系统**：能跑通全流程、能看懂架构图、认识每个开发
- **第一个月做出一个可见贡献**：环境冒烟脚本、一条自动化、一份测试 checklist——小的快速赢建立信任
- **持续输出**：小团队看结果，每个版本的质量数据是你存在的证明

### 收尾：讲选择的清醒

小团队给你的是「**从零搭体系的完整经历**」（大厂螺丝钉给不了），要求的是**自驱和全能**（没人带你定方向）——这个 trade-off 想清楚说明你真理解自己在选什么。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 初创和小公司的招聘里这是高频场景题（大厂流程化的人在野蛮环境里常水土不服），考察的是「流程的因地制宜能力」——懂为什么有流程、才能懂什么时候不要流程，只会执行流程的人到没流程的环境就瘫痪 |
| 过线标准 | 最小够用的理念 + 止血点起步的建设路径 |
| 区分度 | 讲一人测试的「关键人不是所有人」定位、讲第一个月快速赢的是真经历过或深刻思考过的 |
| 减分项 | 「把大厂的完整流程引进来」，教条主义，会把小团队搞死；或「小团队不需要流程」，从一个极端到另一个极端 |
