# 04｜冒烟测试谁来做？不通过怎么处理？

> 开场先分清定位：冒烟是**提测的验收门**（主流程能不能走通是能不能开始正式测试的前提），**不是测试用例的一部分**。

## 回答思路

### 第一步：谁来做——讲主流的两种模式并给判断

- **开发自测冒烟**：提测标准的一部分，开发提供自测记录，测试抽验——最理想，问题在源头拦截
- **测试执行冒烟**：测试拿开发给的冒烟用例集跑——常见模式，要点是**冒烟集固化**（核心主流程的固定用例集，不临时挑）

两种模式各讲利弊，说明你见过不同的团队实践。

### 第二步：冒烟集怎么维护给细节

- **从核心业务主流程提炼**：十到三十条为宜，分钟级到小时级跑完
- **版本演进时更新**：新核心功能进冒烟集
- **有条件就自动化**：冒烟自动化后提测自验变成机器的事，门禁自动执行

维护动作讲出来说明真管过这个资产。

### 第三步：不通过的处理讲纪律

- **立即打回不开测**：继续测就是浪费产能测一个废版本
- **打回要留痕**：记录打回原因和次数，数据用于推动开发自测质量
- **重复打回升级**：连续两三次打回要拉开发负责人对齐，流程问题走流程解决

### 收尾：讲冒烟的另一层价值

冒烟集是版本的「**心电图**」——正式测试期间每天跑一遍冒烟能快速发现「改 A 坏 B」的致命问题，它的用途不止提测那一刻。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 冒烟是流程里最小的门禁但执行率最低（大量团队的冒烟是形式），企业考察的是你真把这个门禁当真吗 |
| 过线标准 | 两种模式 + 不通过的打回纪律 |
| 区分度 | 讲冒烟集固化维护、讲每日冒烟当心电图的是有资产化意识的 |
| 加分项 | 冒烟自动化接门禁的实践 |
| 减分项 | 冒烟「大概点一下没问题就开始测」，既无标准集也无打回动作 |
