# 12｜上线后用户反馈了问题，你作为测试怎么响应？

> 开场先讲响应的**时序纪律**：第一时间定性（是 bug 还是使用问题还是需求争议，快速分类定响应级别）、马上复现（用户反馈的环境和路径在测试环境复现，复现结论决定后续所有动作）——前两步的快慢决定响应质量。

## 回答思路

### 第一步：讲定位和处置

- **复现了**：评估严重度走紧急修复流程，测试参与修复验证和回归
- **复现不了**：收集用户侧信息（版本、设备、操作路径、截图，通过客服或反馈渠道）、挂观察（关联监控日志看同类报错）
- **不是 bug**：给用户和客服准确的使用说明——测试最懂产品行为，响应里有专业价值

### 第二步：讲测试的自查（本题的核心环节）

- **这个问题为什么测试没发现**：用例缺失、环境差异、场景概率、需求漏洞——归因分类
- **当天就补**：回归用例立刻补上，防同类复发
- **如实同步**：漏测的归因诚实地进复盘，不藏着

### 第三步：讲沉淀的动作

- **用户反馈渠道的定期巡检**：每周过一遍反馈池，测试视角挖潜在的批量问题
- **反馈的分类统计**：哪类问题反馈最多，反推测试盲区
- **高发问题模式进测试 checklist**

### 收尾：给认知

线上反馈是测试的「**免费评测集**」（真实用户在帮你测）——把反馈当资产的团队越测越准，把反馈当麻烦的团队重复踩坑，**这个态度的分野决定测试的水平曲线**。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 线上响应是测试右移的基本功（企业考察「上线后你还管不管」），这题综合了偶现处理、漏测自查、用户视角三件事——一个环节薄弱就露馅，是中级测试的实战综合题 |
| 过线标准 | 响应时序（定性、复现）+ 漏测自查归因 |
| 区分度 | 讲反馈池定期巡检、讲「反馈是免费评测集」的是有右移运营意识的 |
| 加分项 | 复现不了时通过客服收集信息的渠道动作 |
| 减分项 | 上线后的问题「开发修就好了测试配合验证」——自查和沉淀环节全无，右移认知为零 |
