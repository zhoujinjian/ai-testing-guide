# 05｜性能测试什么时候介入？完整的性能测试流程是什么？

> 开场先讲介入时机分三个阶段——能把前两阶段讲出来的，是有**左移意识**的人。

## 回答思路

### 第一步：介入时机分三个阶段

| 阶段 | 做什么 |
| --- | --- |
| **架构阶段** | 评审技术方案时看性能设计（缓存、异步、分库分表、扩容方案）——这时候介入最便宜 |
| **开发阶段** | 核心接口的开发自测压一下，问题不过夜 |
| **上线前** | 完整的专项性能验证（多数团队只做到这一阶段） |

### 第二步：完整流程分七步讲

需求分析（指标目标、业务场景模型）→ 方案设计（场景、数据、环境、监控）→ 环境准备（被测环境、压测机、监控部署）→ 脚本开发（协议模拟、参数化、断言）→ 场景执行（基准、负载、压力、稳定性按序跑）→ 监控分析（指标联动定位瓶颈）→ 报告输出（结论和优化建议）——**七步每步有明确产出物**。

### 第三步：讲目标先行这个原则（得分核心）

性能需求不明确时先和业务方对齐：预期日活多少、峰值 QPS 估算、可接受 RT 上限。拿不到业务数据就用**线上监控的历史峰值 × 放大系数**——这个「从业务量推性能目标」的推导过程是本题得分核心。

### 第四步：讲执行纪律

**每轮压测只改一个变量**（并发数或配置）——多变量同改数据没法归因，这个细节是实验素养的体现。

### 收尾：讲闭环

报告不是终点——优化后必须**复压验证**，前后对比数据进报告，问题关闭才算项目结束。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 流程和产出物讲不齐的人只能做执行者，企业为「能独立交付专项」的人付专项薪资 |
| 过线标准 | 流程完整（目标到报告闭环）+ 目标先行的意识 |
| 区分度 | 讲「业务量推目标」的具体推导、讲单变量原则的是真做过归因分析的 |
| 加分项 | 架构阶段介入的左移认知 |
| 减分项 | 流程从「写 JMeter 脚本」开始，前面没有目标分析，暴露只会执行 |
