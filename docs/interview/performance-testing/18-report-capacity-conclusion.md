# 18｜性能测试报告怎么写？容量结论怎么给？

> 开场给报告的标准骨架——报告是给**决策者看的**，不是给自己看的。

## 回答思路

### 第一步：报告结构标准骨架

1. **背景与目标**：当初定的指标线
2. **测试方案摘要**：环境、场景、数据
3. **结果数据**：核心指标对比目标线的达标表格
4. **问题与风险**：发现的瓶颈、未达标项、遗留风险
5. **结论与建议**：能不能上、容量是多少、下一步优化什么

### 第二步：数据呈现讲门道

- **给曲线不只给数字**——TPS 和 RT 随并发变化的联动曲线最有说服力
- 给分位值不只给平均
- 前后对比（优化前后的柱状对比）
- 达标结论用红绿灯表

### 第三步：容量结论的给法（核心）

- 当前配置在目标 RT 内**最大支撑 TPS 多少**
- 对应业务量多少（**换算成日活或订单量**）
- 离预期峰值的**余量百分比**
- 扩容建议（加几台机器支撑目标流量、线性度预估）

容量结论是给老板做预算的——**要能直接拿去用**。

### 第四步：讲风险和局限的诚实披露

环境折算的失真风险、未覆盖的场景、数据局限——报告写明**置信边界**反而是专业的表现，拍胸脯保证一切的报告不可信。

### 收尾：讲报告的追踪

报告里的问题清单要进缺陷跟踪，优化项复压后更新报告版本——**报告是活文档**，不是交付即终点的作业。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 报告是性能测试的最终交付物，写得清不清楚决定专项价值能不能被承认——企业要的是能把技术数据翻译成业务决策语言的人 |
| 过线标准 | 报告结构完整 + 容量结论有具体给法 |
| 区分度 | 讲曲线联动、分位值呈现、余量百分比换算的是老手；只贴一张结果表格的是新手 |
| 加分项 | 主动披露测试局限和置信边界 |
| 减分项 | 报告只有数据没有结论，或结论是「性能基本正常」这种和稀泥话术 |
