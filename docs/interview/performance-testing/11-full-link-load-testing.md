# 11｜什么是全链路压测？和普通压测的区别是什么？

> 开场先给定义：拿真实业务流量模型，在**真实生产环境**，对从入口到数据库的整条调用链路（网关、服务、缓存、消息、数据库）施加压力——普通压测压单系统或单接口，全链路压测压整条链路。

## 回答思路

### 第一步：讲为什么必须做全链（得分核心）

单系统各自压测都达标，串起来照样出问题——**瓶颈藏在系统的交界处**：服务 A 调 B 时的连接池竞争、共享数据库的锁冲突、缓存击穿连锁。微服务架构下这类跨系统问题只有全链路能暴露。

### 第二步：讲核心技术挑战——流量隔离

压测流量不能污染生产数据：

- **流量染色**：压测请求打上标识全程透传
- **影子体系**：影子库影子表、影子 topic、影子缓存 key

写请求落到影子存储，读请求模拟放大的缓存行为——这套体系能讲出骨架，说明接触过大厂级实践。

### 第三步：讲风险控制

- 压测前：环境巡检和容量预估
- 压测中：分级限流和熔断预案
- 影响窗口：低峰深夜
- **一键停止能力**

全链路压测是高危操作——**纪律比技术重要**。

### 收尾：给适用判断

全链路压测成本高（体系搭建以年计），只有**大促级场景和大规模微服务集群**才值得投入；中小团队做核心链路的准全链路（关键依赖 mock 或降级）更务实。不吹不贬的判断显成熟。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 全链路压测是大厂性能岗的分水岭题（阿里双 11 体系、字节美团都有自研平台）——企业用它区分「用过 JMeter」和「懂生产级压测体系」，后者稀缺且贵 |
| 过线标准 | 定义清楚 + 「交界处瓶颈」的必要性认知 + 流量染色影子库概念 |
| 区分度 | 讲影子 topic、影子缓存 key、一键熔断这些体系细节的是真参与过的 |
| 加分项 | 对投入产出的务实判断（什么团队不值得做） |
| 减分项 | 把全链路压测理解成「把很多接口都压一遍」，概念完全错误 |
