# 03｜TPS、QPS、RT、并发数这些指标是什么关系？

> 开场逐个定义，再讲关系——指标体系是性能测试的通用语言，这是硬门槛题。

## 回答思路

### 第一步：逐个定义

- **TPS**：每秒处理的事务数（一个事务可能含多个请求——下单事务含查库存、创建订单、扣减）
- **QPS**：每秒查询数，纯指单个接口每秒被处理的次数
- **RT**：响应时间，从发出请求到收到响应的耗时
- **并发数**：同一时刻同时在处理中的请求或虚拟用户数

### 第二步：讲 TPS 和 QPS 的关系

一个事务拆成多个请求时 **TPS 小于 QPS**，单接口场景两者相等——日常沟通常混用，但面试要能说清区别。这个辨析是本题的送分核心。

### 第三步：给出核心公式

**并发数 = TPS × RT**（利特尔法则）。同一个系统 RT 越高，同样并发数下吞吐越低——用这个公式反推：想要 TPS 上去，要么加并发（扩容）、要么降 RT（优化）。把公式和优化手段挂钩，说明你真用它做过推算。

### 第四步：举一个算例

目标 TPS 1000、预期 RT 0.2 秒 → 需要并发 200——**现场口算一遍**，面试官立刻知道你会用公式而不是背概念。

### 收尾：讲指标间的关系张力

加压初期 TPS 涨 RT 稳，到拐点后 **TPS 停涨、RT 陡升**——这个曲线形状是判断系统容量的核心证据。性能分析看的就是这几个指标的**联动曲线**，而不是单点数值。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 指标体系是和开发、架构对话的通用语言，分不清 TPS 和并发的人报告都写不明白 |
| 过线标准 | 四个指标定义准确 + 并发 = TPS × RT 的公式及运用 |
| 区分度 | 现场口算算例、讲拐点曲线联动的是做过的；背定义的是没碰过真实压测 |
| 加分项 | 利特尔法则的名字，或事务和请求在 TPS 上的换算辨析 |
| 减分项 | 说「并发数越高 TPS 越高」，不知道拐点的存在 |
