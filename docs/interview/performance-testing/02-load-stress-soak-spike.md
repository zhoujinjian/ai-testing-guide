# 02｜负载测试、压力测试、稳定性测试、尖刺测试有什么区别？

> 开场一句话各定位再展开——这是性能面试的第一道概念题，类型分不清说明没做过完整专项。

## 回答思路

### 第一步：四种类型各回答什么问题

| 类型 | 做法 | 回答什么 |
| --- | --- |
| **负载测试** | 加压到预期目标 | 正常负载下达不达标 |
| **压力测试** | 一直加压超过极限 | 极限在哪、崩成什么样 |
| **稳定性测试** | 目标负载长时间持续运行（几小时到几天） | 能不能稳住——抓内存泄漏、连接泄漏这类慢性病 |
| **尖刺测试（spike）** | 流量瞬间冲高再回落 | 突发流量扛不扛得住 |

### 第二步：给场景对号入座

日常版本回归跑**负载**、新系统摸底跑**压力**、大促前必跑**稳定性加尖刺**、秒杀场景重点看**尖刺**——把测试类型和业务场景配对讲，说明你会按需选型。

### 第三步：讲过载后的重点观察项（SRE 视角）

压力测试压垮系统不是结束，重点看三件事：

1. 崩溃时有没有**熔断降级**保护用户
2. 流量回落后能不能**自动恢复**
3. 恢复过程**丢不丢数据**

讲出来直接上一个段位。

### 第四步：讲个常见误区

只跑负载测试报个绿灯就下结论「性能没问题」——**没压过极限的系统你不知道它过载时的行为**，线上流量一旦超预期就是裸奔。这个风险意识是加分句。

### 收尾：给执行配比

一次完整的性能专项：**基准摸底 → 负载验证 → 压力探底 → 稳定性浸泡**按这个顺序串起来，各阶段回答各的问题。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 性能面试的第一道概念题，企业用这题快速分层，答全了才有后面的方案设计题 |
| 过线标准 | 四种类型定义准确 + 各自回答什么问题 |
| 区分度 | 讲过载行为观察（熔断、恢复、数据）的是有生产视角的；只会背定义的是没压垮过系统 |
| 加分项 | 能指出「只跑负载测试」的常见误区 |
| 减分项 | 负载和压力混为一谈，基础概念错误直接出局 |
