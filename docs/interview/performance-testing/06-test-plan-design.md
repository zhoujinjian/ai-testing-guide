# 06｜给你一个系统，性能测试方案怎么设计？

> 开场先**反问三个问题**再作答：性能目标是什么（业务量、响应时间要求）？压测范围是全链路还是核心接口？环境和数据能不能用生产的量级？——这个反问动作本身就在得分。

## 回答思路

### 第一步：方案给标准结构（六要素）

1. **目标与指标**：从业务量推导，写清 TPS、RT 分位值、错误率、资源水位的目标线
2. **场景设计**：单接口基准、核心业务链路混合、异常场景
3. **数据方案**：参数化数据量、铺底数据、数据隔离和清理
4. **环境方案**：环境规格、监控部署
5. **执行计划**：轮次、加压模型、每轮观察项
6. **风险预案**：压测压挂了怎么办、限流保护阈值

### 第二步：混合场景是重点展开对象

按线上真实流量比例构造各接口的配比（浏览七成、下单两成、支付一成）——**只压单接口的方案测不出资源共享冲突**，混合模型才接近真实。能讲「流量模型」这个词，说明真设计过。

### 第三步：讲监控的配套

应用层（RT、QPS、错误率）、资源层（CPU、内存、磁盘、网络）、中间件层（连接池、线程池、队列积压）、数据库层（慢查询、锁等待）——**压测不配监控等于蒙眼开车**，监控点位清单是方案必备章节。

### 收尾：讲评审

性能方案要过技术评审，让开发和架构确认压测接口的代表性、数据构造的合理性——**方案被挑战后修订的过程恰恰是价值所在**。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 性能岗的核心大题，等同功能测试的「怎么开展测试」——方案有没有结构、有没有目标推导，一开口就分层了 |
| 过线标准 | 方案六要素齐全 + 有流量模型的混合场景意识 |
| 区分度 | 讲目标推导过程、单变量执行纪律、风险预案的是方案 owner 视角；罗列工具和步骤的是执行者视角 |
| 加分项 | 压测熔断保护（防止把生产或共享环境压挂） |
| 减分项 | 上来就说「用 JMeter 录脚本加线程组」，没目标没场景没监控，方案意识为零 |
