# 19｜质量内建是什么意思？怎么在团队落地？

> 开场先给定义和动机：**质量内建（Build Quality In）**指质量在研发过程的每个环节被「**制造**」出来，而不是最后被「测试」出来。

## 回答思路

### 第一步：经济学依据

**缺陷成本曲线**——需求期发现成本一倍、上线后发现成本百倍。测试兜底模式等于把最贵的质量成本后置。定义加成本逻辑，理论根基立住。

### 第二步：讲落地的前移动作

| 阶段 | 动作 |
| --- | --- |
| **需求阶段** | 需求评审有可测性检查（验收标准清晰吗、边界条件写了吗） |
| **开发阶段** | 单测覆盖 + 静态扫描 + code review 质量把关（缺陷拦截在编译时和评审时）；**提测自检门禁**（冒烟自测通过才许提测） |
| **测试阶段** | 测试重心从「找 bug」转向「**设计防 bug 的检查项**」（用例设计的输入前移到开发自测用例） |

### 第三步：讲右移的内建

上线不是质量终点——灰度验证 + 监控告警把质量保障延伸到生产，线上问题快速回流成改进（合集二右移的呼应）。**内建是全生命周期的，不是只在左边。**

### 第四步：讲度量的牵引

用「**缺陷检出阶段分布**」衡量内建效果：测试期发现占比升、线上逃逸占比降、需求期拦截占比升——**内建不是口号，是用指标验证的移动过程**。

### 收尾：讲落地的难点和策略

开发会觉得「测试的活转嫁给我」——推动要靠：

- **共赢设计**：自测门禁挡掉的返工其实省了开发自己的时间，用数据讲给开发听
- **工具降低成本**：自测工具一键跑、用例模板现成

内建改变的是**责任分工**——组织阻力大于技术阻力，这个判断讲出来是管理成熟度。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 质量内建是 DevOps 和敏捷共同的核心主张——考察从「测试执行者」到「质量体系设计者」的角色升级，是测试转管理和效能方向的核心认知题 |
| 过线标准 | 定义加缺陷成本逻辑 + 左移右移的落地动作 |
| 区分度 | 讲检出阶段分布的度量牵引、讲组织阻力大于技术阻力的判断的是推动过的 |
| 加分项 | 共赢设计和工具降低成本的推动策略 |
| 减分项 | 把内建讲成「开发自己测测试没事干」，理解完全跑偏 |
