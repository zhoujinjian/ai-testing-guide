# 20｜效能团队（工程效能部）是干什么的？测试团队和它怎么协作？

> 开场先给效能团队的**职责地图**——四块职责报出来，这个部门的画像就清晰了。

## 回答思路

### 第一步：四块职责

| 职责 | 内容 |
| --- | --- |
| **工具链建设** | DevOps 平台、CI/CD 流水线、测试环境治理 |
| **度量体系** | 数据采集、指标定义、看板平台 |
| **流程改进** | 跨团队的价值流优化、规范制定 |
| **标准与推广** | 最佳实践沉淀和落地辅导 |

### 第二步：讲它存在的逻辑

研发效能的瓶颈多数是**系统性和跨团队的**（环境争用、工具割裂、流程等待）——单业务团队没有动力和权限解决横向问题，需要一个专职团队做「横向基础设施」。**效能团队的本质是研发体系的中台。**

### 第三步：讲测试团队和它的三个协作界面

| 界面 | 协作内容 |
| --- | --- |
| **工具层** | 测试平台和 CI/CD 的集成、环境治理的测试诉求提报 |
| **数据层** | 测试效能指标进公司效能大盘的口径对齐 |
| **改进层** | 测试环节的效能瓶颈分析找效能团队合作（如测试环境排队问题需要基础设施改造） |

能讲具体的协作故事最好：「我们和环境治理组共建了测试环境按需申请，排队时长从两天降到十分钟」。

### 第四步：讲协作的常见摩擦和化解

- 效能团队推的工具不符合测试实际（强推统一平台但测试场景特殊）→ 化解靠**测试团队主动参与需求评审**（把测试场景喂进设计），而不是事后抱怨
- 测试自建的轮子和公司标准冲突 → 化解靠**接口标准化加逐步归并**的路线

### 收尾：给职业视角

测试工程师转效能方向是**自然路径**（懂研发过程 + 有工程能力 + 有质量视角）——效能团队里**测试背景的人恰恰是最稀缺的**（多数效能团队开发背景居多、缺质量维度的思考）。这个职业机会的判断，给想转型的听众指了条路。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 大厂普遍设有工程效能部门（或叫研发效能、DevOps 平台团队）——考察组织认知和协作经验，同时是往效能方向转型的候选人的动机检验题 |
| 过线标准 | 职责地图 + 三个协作界面 |
| 区分度 | 能讲具体协作故事、能讲摩擦化解的是真协作过的；只会说「他们提供工具我们用」的是浅层接触 |
| 加分项 | 测试背景在效能团队的稀缺性认知（职业洞察） |
| 减分项 | 「效能团队就是管流程规范的官僚」，只有情绪判断没有结构认知 |
