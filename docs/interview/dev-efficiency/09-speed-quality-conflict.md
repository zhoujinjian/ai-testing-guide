# 09｜效能指标之间会打架，速度和质量冲突怎么办？

> 开场先**承认冲突的真实性**：交付周期和缺陷逃逸率天然互拉（赶周期容易牺牲质量、求稳容易拖慢交付）——否认冲突的存在是理论派，**直面它才谈得上管理它**。

## 回答思路

### 第一步：给「管理冲突」的三个机制

| 机制 | 逻辑 |
| --- | --- |
| **风险分级** | 不是所有变更都要同样的质量流程——核心链路严管、长尾快速通行，把质量成本花在刀刃上 |
| **自动化兜底** | 质量检查自动化后冲突大幅缓和——门禁自动跑不占人力时间，**快和稳从对立变成并行** |
| **小批量交付** | 小步快跑让每次变更的风险面变小——出问题影响小、恢复快。DORA 精英团队「又快又稳」的秘密就在这 |

### 第二步：讲指标设计层面的防冲突

给速度类指标配质量类「**护栏指标**」——考核交付周期必须同时监控变更失败率，失败率恶化说明快是虚的。**指标成对出现**是体系设计的基本功（02 题埋的伏笔在这收口）。

### 第三步：讲冲突升级时的决策框架

业务形态决定优先序：

- **交易类系统**质量优先（资损不可逆）
- **增长类业务**速度优先（试错学习价值高）

没有普适答案——把冲突决策交给**业务画像**，而不是个人偏好。

### 收尾：给认知收口

速度和质量**不是零和**——长期看，高质量反而是高速度的前提（返工和故障处理是最大的时间浪费）。短期冲突要管理，长期目标是把两者做成**正循环**。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 效能推进者天天面对「快了就漏、稳了就慢」的团队抱怨——答得好说明真在效能一线干过 |
| 过线标准 | 承认冲突 + 三个管理机制 |
| 区分度 | 讲护栏指标设计、讲小批量交付逻辑的是体系级思考；只会说「平衡好就行」的没有方法 |
| 加分项 | 按业务形态定优先序的决策框架 |
| 减分项 | 「质量第一其他都不重要」或「先上线再说」——单边立场没有管理手段 |
