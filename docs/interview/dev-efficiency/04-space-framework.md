# 04｜SPACE 框架听说过吗？和 DORA 什么关系？

> 开场先给 SPACE 五个字母的含义——答得出说明你**跟进过效能方法论的前沿**（微软和 GitHub 的研究产出）。

## 回答思路

### 第一步：五个维度

| 字母 | 维度 | 含义 |
| --- | --- | --- |
| **S** | Satisfaction 满意度 | 开发者工作满意度和幸福感 |
| **P** | Performance 绩效 | 特点是**绩效看群体产出，不量个人** |
| **A** | Activity 活跃度 | 活动量类指标 |
| **C** | Communication 沟通协作 | 协作流畅度 |
| **E** | Efficiency 效率流程 | 流程顺畅度 |

### 第二步：讲 SPACE 的核心主张

1. 效能是**多维的**——没有单一指标能代表它，必须多维组合看
2. **明确反对度量个人**——个人层面的度量必然失真和被博弈

这两个主张是它最有价值的部分。

### 第三步：讲和 DORA 的关系（互补而非替代）

- **DORA** 管交付管道的**客观结果**（流程视角）
- **SPACE** 补**人的维度和协作维度**（人的视角）

成熟团队的实践：DORA 做骨架 + SPACE 的维度做补充（满意度调查、协作分析）——两者拼起来才是完整的效能视图。

### 第四步：讲使用时的务实取舍

小团队先把 DORA 跑顺（数据自动采，成本低），SPACE 的满意度维度用**轻量的季度调查**补上——别教条地全套上马，方法论要和团队规模匹配。

### 收尾：给认知的收口

两个框架的共同底层是「**效能是系统属性不是个人属性**」——度量系统、改进系统、让好系统里的人自然产出好结果。这是现代效能观和老式「管出勤查工时」的根本分野。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 这是效能方向的进阶识别题（SPACE 比 DORA 冷门）——大厂效能团队的面试官用它找「同行」：答不出不致命，答得好直接加分 |
| 过线标准 | 五维度含义 + 和 DORA 的互补关系 |
| 区分度 | 讲「反个人度量」主张、讲「系统属性」收口的是真研究过的 |
| 加分项 | 按团队规模的务实取舍建议 |
| 减分项 | 把 SPACE 说成 DORA 的升级版（替代关系），关系理解错误 |
