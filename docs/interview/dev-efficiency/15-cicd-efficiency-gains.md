# 15｜CI/CD 建设对效能的提升体现在哪些指标上？

> 开场按**指标对应**讲提升机制——机制加指标成对讲，体系感立住。

## 回答思路

### 第一步：机制与指标的对应

| 建设机制 | 提升的指标 |
| --- | --- |
| 流水线自动化让发布从「仪式」变「日常」 | **部署频率**（一天多次成为可能） |
| 提交到上线的等待从人工审批的小时天级压到流水线的分钟级 | **变更前置时间** |
| 自动化测试门禁和标准化发布降低人为失误 | **变更失败率** |
| 标准化回滚和环境一致性让恢复提速 | **MTTR** |

### 第二步：讲 CI/CD 改变的是什么本质

它消灭的是「**等待和不确定性**」——等环境、等审批、等发布窗口，以及「这次发布会出什么事」的赌博感。把交付从项目制的手工活变成**流水线的标准品**——人的精力从「搬运和仪式」转向「设计和判断」。

### 第三步：讲建设的关键组成（四件套）

1. **流水线**：构建测试部署的自动化链
2. **质量门禁**：自动化测试卡在流水线里，不过不合并
3. **环境管理**：环境的一致性和按需创建
4. **发布策略**：灰度、蓝绿、回滚的标准化

### 第四步：讲分阶段的落地路径和各阶段的指标变化

1. 第一阶段**构建自动化**：构建成功率从手工的八成到九成九
2. 第二阶段**测试集成**：前置时间里测试等待的大头被压缩
3. 第三阶段**部署自动化加发布策略**：部署频率数量级提升

每阶段盯着对应指标看收益——**建设效果可验证**。

### 收尾：讲测试在 CI/CD 建设里的角色

自动化用例是流水线的弹药（合集三 17 题的 CI 集成）、测试左移让问题在流水线前段拦截——测试团队是 CI/CD 效能故事里的**关键共建方**，而不是旁观者。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | CI/CD 是效能提升的第一杠杆（几乎所有效能改进故事从它开始）——检验候选人有没有算过建设的投入产出账 |
| 过线标准 | 指标和机制的对应关系 + 建设四件套 |
| 区分度 | 分阶段路径和各阶段指标收益的是主导过建设的；只讲「自动化很方便」的是用过没建过 |
| 加分项 | 消灭「等待和不确定性」的本质概括、测试团队的共建角色 |
| 减分项 | 把 CI/CD 说成「装个 Jenkins」，认知停在工具安装层 |
