# 02｜研发效能的度量体系怎么搭？有哪些维度的指标？

> 开场先给**分层的指标框架**再报指标——框架感是第一得分点。

## 回答思路

### 第一步：四个维度各报代表指标

| 维度 | 回答什么 | 代表指标 |
| --- | --- | --- |
| **交付速度** | 多快 | 需求交付周期（提出到上线）、需求平均开发周期、部署频率 |
| **交付质量** | 多好 | 变更失败率、缺陷逃逸率、线上故障数和恢复时长 |
| **交付能力** | 能不能持续 | 构建成功率、自动化覆盖率、回滚时长 |
| **成本效率** | 多省 | 人力投入和需求吞吐的比值、基础设施成本 |

每个指标一句话讲清「它衡量什么」。

### 第二步：讲指标间的组合关系

**单一指标都会骗人**：速度单独看会逼出低质量交付、质量单独看会逼出不敢发布。指标要**成组看**（快不快 + 稳不稳 + 值不值）——健康度是组合出来的，不是单指标拉满。

### 第三步：讲落地路径

从现有工具链能**自动采集**的指标起步（Git、CI、项目管理工具里都有数据）——不要一上来建大而全体系，先跑通「采集、展示、解读」的**最小闭环**再扩维度。

### 收尾：讲视角分层

同一套数据给三层看不同的东西：

- **管理层**看趋势和投入产出
- **团队级**看瓶颈定位
- **个人不考核**（只做自我改进参考）

视角分层是体系能不能活的关键设计。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 企业效能建设的第一步就是建指标体系——报得出维度框架和代表指标、讲得出指标组合关系的，是建过体系的 |
| 过线标准 | 维度框架 + 每维度两三个指标且懂含义 |
| 区分度 | 讲「指标成组看防互骗」、讲三层视角的是有体系设计经验的；报一堆指标名没有结构的是背的 |
| 加分项 | 从工具链自动采集起步的务实路径 |
| 减分项 | 指标清单里混入「代码行数」「工作时长」这类公认的反指标，暴露度量认知陈旧 |
