# 10｜效能数据怎么采集才真实？工具链埋点和人工填报怎么选？

> 开场先立原则：**能自动采集的绝不人工填报**——这是本题的定盘星。

## 回答思路

### 第一步：人工填报的两个致命伤

- **失真**：人趋利避报，填报的数据反映的是「想让你看的」
- **成本**：填报本身消耗产能

自动采集（事件发生即记录）**天然真实且零边际成本**。

### 第二步：讲自动采集的数据源地图

| 数据源 | 事件 |
| --- | --- |
| **代码仓库** | 提交、合并、评审记录 |
| **CI/CD** | 构建、部署、回滚事件 |
| **项目管理工具** | 需求状态流转的时间戳 |
| **缺陷系统** | bug 生命周期 |
| **监控系统** | 线上指标 |

工具链的事件日志就是效能数据的**金矿**——集成 API 拉事件流进数据仓库，这是效能平台的标准架构（13 题展开）。

### 第三步：讲必须人工采集的部分怎么办

满意度、协作感受这类**主观维度**（SPACE 的部分）没法埋点——用**周期性匿名调查**（季度一次、轻量几题、匿名保真实）。主观指标低频采、客观数据高频采，两类数据各归各位。

### 第四步：讲数据质量的治理

- **口径统一**：「需求完成」以什么状态为准——全公司一个定义
- 脏数据清洗（工具误操作产生的假事件）
- 数据延迟的容忍度设计

数据治理的严谨度决定上层指标可信度。

### 收尾：给反例警示

见过「效能日报要手动填 Excel」的做法——填报花的时间比它省的时间多，数据还是美化过的。**这种度量不如不量。**

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 数据真实性是效能体系的地基，地基歪了上面全塌——只谈指标不谈采集的候选人是纸上谈兵 |
| 过线标准 | 自动化优先原则 + 数据源地图 |
| 区分度 | 讲口径统一、脏数据治理的是真建过数据管道的 |
| 加分项 | 主观维度用匿名调查的补位设计 |
| 减分项 | 方案里大量依赖人工填报，数据可信度归零 |
