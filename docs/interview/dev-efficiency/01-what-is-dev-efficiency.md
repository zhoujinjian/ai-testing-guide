# 01｜什么是研发效能？为什么要度量研发效能？

> 开场先给定义再拆解：研发效能是团队「**持续、高质量、高效率地交付业务价值**」的能力——三个关键词缺一不可。

## 回答思路

### 第一步：三角定义先立住

只快不好（bug 一堆）、只好不快（半年发一版）、又快又好但交付的东西**没价值**（做了一堆没人用的功能）——都不是高效能。

### 第二步：效能和效率的区别（认知第一分水岭）

| | 效率 | 效能 |
| --- | --- | --- |
| 定义 | 单位投入的**产出量**（写了多少代码跑了多少用例） | 单位投入的**价值量**（交付的东西带来多少业务结果） |
| 度量 | 容易（数数就行） | 难（要关联业务结果） |

大量组织的度量失败就是把效率当效能量——代码行数涨了，业务没变化。

### 第三步：为什么要度量给三个理由

1. **看见**：复杂协作的研发过程是个黑盒——度量让它可观察（瓶颈在哪、卡在谁那），没有数据全靠感觉吵
2. **改进**：度量是改进的起点——没有基线就没有对比，没有对比就不知道改进有没有用
3. **对齐**：用同一套语言和管理层、跨团队对话，争取资源时有据可依

### 第四步：讲度量的边界（防止走火入魔）

度量是**手段不是目的**——古德哈特定律警告「**指标一旦成为目标就不再是好指标**」。度量的正确用法是发现问题和验证改进，不是考核个人（11 题展开这个坑）。

### 收尾：给定位

效能度量的终极目的是建立「**反馈回路**」——让团队像优化代码一样优化自己的工作方式，度量体系是这个回路的仪表盘。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 降本增效大环境下每个企业都在做或想做效能度量，但大量项目做成了「报表工程」或「监控员工」——企业通过这题找认知正确的人 |
| 过线标准 | 价值三角定义 + 效能和效率的区分 |
| 区分度 | 主动讲古德哈特定律和度量边界的是有理论素养的；把效能等同于「干活快」的认知粗糙 |
| 加分项 | 「反馈回路」的定位表述 |
| 减分项 | 把度量直接等同于「考核工具」，方向性危险 |
