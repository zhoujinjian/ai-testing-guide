# 08｜MTTR、MTTI 这些线上质量指标是什么？怎么用？

> 开场先把**缩写家族**讲清——报得出这个家族，说明懂 SRE 视角。

## 回答思路

### 第一步：三个时间轴指标

| 指标 | 含义 | 考什么 |
| --- | --- | --- |
| **MTTD** 平均发现时间 | 故障发生到被发现的时长 | 监控能力 |
| **MTTI** 平均识别时间 | 发现到定位原因 | 定位能力 |
| **MTTR** 平均恢复时间 | 发生到恢复 | 应急能力 |

三个连起来就是故障的「**发现、定位、恢复**」全链路效率。

### 第二步：讲它们和测试的关系（关键定位）

- 传统测试管「上线前拦住」（**防御**）
- 线上质量指标管「上线后快速止损」（**韧性**）

逃逸率再低也不可能为零——所以「快速恢复」和「事前拦截」**同等重要**。测试团队从「质量守门员」扩展为「**全周期质量参与者**」（呼应合集二的测试右移）。这个视野是本题得分核心。

### 第三步：讲怎么用这些指标做改进（指标长在哪改进打在哪）

- **MTTD 长** → 补监控告警覆盖（核心接口成功率阈值、资源水位）+ 用户反馈渠道响应
- **MTTI 长** → 建设定位工具（trace 链路、日志聚合、预案知识库）
- **MTTR 长** → 做预案演练（回滚脚本化、降级开关预埋）+ 故障复盘推自动化止损

### 第四步：讲故障复盘和这些指标的联动

每起故障复盘产出改进项（监控补盲、预案建设、流程修正）——改进项的落地效果用**下个周期的 MTT 系列指标验证**。指标、复盘、改进形成闭环。

### 收尾：给行业参考值

高成熟团队**分钟级发现定位、小时级恢复**；传统团队故障要等用户投诉才知道（MTTD 以小时天计）——差距就是监控和预案的体系建设差距。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 线上质量是企业的生命线指标（阿里云真题盘点确认 MTTR/MTTI 是考核点）——懂这套指标说明有全周期质量视野，在测开和测试管理岗是高区分度能力 |
| 过线标准 | 三个指标含义 + 和测试工作的关系定位 |
| 区分度 | 按指标长短板给对应改进建设的是真做过线上质量运营的 |
| 加分项 | 指标、复盘、改进的闭环设计 |
| 减分项 | 认为故障处理纯是运维的事和测试无关，视野停在发布前 |
