# 17｜讲一个你做过的效能提升案例，效果怎么量化的？

> 开场用 **STAR 结构**组织故事——案例题是检验所有效能知识的试金石，前面讲得好不好，一问案例就现形。

## 回答思路

### 第一步：STAR 结构

- **背景**：团队什么痛点、量化现状（回归测试一轮五天占用六人）
- **任务**：目标定在回归压到一天内且逃逸率不升
- **行动**：分几步走（自动化分层建设、造数自助化、CI 集成门禁、流程裁剪）
- **结果**：回归四十分钟、逃逸率持平略降、释放的人力转向新场景探索

### 第二步：量化效果讲三个层次（递进最有说服力）

1. **直接效果**：回归耗时从五天到四十分钟
2. **衍生效果**：释放的人力做了什么（补了多少自动化和探索性测试）
3. **业务效果**：发布频率从双周变按需、需求交付周期缩短多少

### 第三步：讲清楚「你的角色」

团队做的事和「你」做的部分要分开——「我负责方案设计和自动化框架搭建，两位同事负责用例迁移」。**贪团队之功据为己有，追问两句就穿帮**；诚实标注角色反而是成熟。

### 第四步：讲踩的坑和修正

过程里遇到的挫折（第一批自动化维护成本爆炸，重构成了接口层为主的分层）和怎么调整的——**有坑的故事才真实，全顺的故事像编的**。

### 收尾：给沉淀

这个案例沉淀了什么**可复用的资产**（框架、流程、度量方法）——好的效能案例不止解决一个问题，还留下了可复制的方法论。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 企业用它区分「学过效能」和「做过效能」——这一题往往直接决定 offer 的档位 |
| 过线标准 | 结构完整 + 三层量化数字 |
| 区分度 | 角色诚实标注、有踩坑修正的、有资产沉淀的是真做过的；只有结果数字没有过程细节的存疑 |
| 加分项 | 衍生效果和业务效果的量化（不止「快了」，还有「省下的人干了什么」） |
| 减分项 | 案例讲成团队流水账没有自己的角色，或数字夸张经不起追问（「效率提升 300%」这种） |
