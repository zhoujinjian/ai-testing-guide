# 06｜缺陷逃逸率怎么算？怎么用它改进质量？

> 开场先给公式和口径——逃逸率是测试效能的**第一结果指标**，也是博弈风险最高的指标之一。

## 回答思路

### 第一步：公式和口径（严谨性是第一层分）

**逃逸率 = 线上发现的缺陷数 ÷（测试发现 + 线上发现的缺陷总数）**

口径要点：

- 分母**包含线上部分**
- 统计周期要和**版本对齐**
- 什么算「线上缺陷」要定义清（用户反馈的算不算、监控发现算不算）

口径不讲清的逃逸率没法对比。

### 第二步：讲它为什么是好指标

它直接度量测试的「**漏**」——比用例执行率、bug 数这些过程指标更贴近结果价值。测试存在的意义就是拦住缺陷，逃逸率是拦截效果的成绩单。

### 第三步：讲怎么用它做改进（本题主体）

先做逃逸缺陷的**归因分类**，四类归因对应四条改进路：

| 归因 | 改进路径 |
| --- | --- |
| 用例缺失（根本没设计到） | 补用例覆盖 |
| 环境差异（测试环境复现不了线上条件） | 推环境一致性 |
| 时间压缩（没测完就上了） | 推动排期保护 |
| 监控盲区（测试发现不了，只能靠线上观测） | 补监控告警 |

**归因加改进的闭环**才是逃逸率的正确用法。

### 第四步：讲每个逃逸缺陷的复盘机制

逃逸 bug 必须**逐个复盘**（为什么没拦住、补什么用例、改什么流程），复盘结论沉淀成检查项——这和合集二「线上问题回流」是同一件事的两个说法。

### 收尾：讲它的陷阱（呼应社区真题讨论）

逃逸率做 KPI 会催生「**刷测试期 bug 数**」压低分母的博弈（多提边角 bug 让分母变大）。防博弈：统计口径限定「**有效缺陷**」（评审后确认的）+ 团队级不个人级考核——**指标设计要预判博弈**。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 逃逸率是测试效能的第一结果指标（ONES、思码逸都列核心），企业要会用它且防得住它的人 |
| 过线标准 | 公式口径严谨 + 归因分类到改进路径 |
| 区分度 | 讲四类归因、讲刷 bug 数的博弈和防法的是深度实践者 |
| 加分项 | 逃逸 bug 逐个复盘的机制设计 |
| 减分项 | 只会算数不会归因改进，或拿逃逸率考核个人——两种都是没用对 |
