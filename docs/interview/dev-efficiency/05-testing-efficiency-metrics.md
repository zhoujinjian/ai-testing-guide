# 05｜测试环节的效能怎么度量？哪些指标是有效的？

> 开场先给测试效能的指标地图——测试是研发链条里**度量最混乱**的环节（用例数 bug 数满天飞）。

## 回答思路

### 第一步：三组指标的地图

| 视角 | 指标 |
| --- | --- |
| **效率侧** | 用例执行自动化率、单版本测试工时、回归耗时（从天到小时的变化）、缺陷平均处理时长 |
| **质量侧** | 缺陷逃逸率（漏到线上的比例）、缺陷检出阶段分布（越早发现越便宜）、用例有效度 |
| **能力侧** | 自动化覆盖率、造数自助率 |

### 第二步：讲有效指标的三条标准

1. **能自动采集**（人工填报的都会失真）
2. **能指导行动**（看到数字知道该干什么）
3. **不可被博弈**（刷数字反而伤害质量）

不达标的宁可不量。

### 第三步：重点讲两个「看着有用其实有毒」的指标

- **用例数量**：会激励人写水用例凑数
- **bug 数量**：会激励测试和开发对立（为提单而提单）

这两个是测试管理史上**翻车最多**的度量——主动点出来，说明见过世面。

### 第四步：讲组合的看法（成组防骗）

- 自动化率要和**逃逸率**一起看（自动化率高但逃逸率也高——说明自动化的都是没风险的场景，假覆盖）
- 回归耗时要和**质量**一起看（快但漏就是灾难）

### 收尾：给基线思维

任何测试效能指标**先测基线再谈改进**——同比环比的**趋势比绝对值有意义**（每个团队业务形态不同，跨团队比绝对值是耍流氓）。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 企业要有能力把测试效能量正确的人——这题直接考察度量素养的专业深度 |
| 过线标准 | 三组指标 + 有效指标的三条标准 |
| 区分度 | 点破用例数和 bug 数的毒性、讲指标成组防骗的是有实战判断的 |
| 加分项 | 趋势比绝对值重要的基线思维 |
| 减分项 | 推荐用例数量或 bug 数量考核测试——度量反模式的活标本 |
