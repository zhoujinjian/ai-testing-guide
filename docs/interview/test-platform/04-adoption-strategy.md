# 04｜怎么避免平台做出来没人用？

> 开场先诊断「没人用」的病因——**先诊断显示你见过尸体**。

## 回答思路

### 第一步：四种病因对应四种死法

1. **做之前没调研**：做的是你以为的痛点，不是团队的真痛点
2. **迁移成本高**：平台比老方法麻烦，人自然留在原地
3. **体验差**：慢、丑、不稳定——用一次就劝退
4. **没有运营**：上线即终点，没人在乎用户用不用得上手

### 第二步：预防手段按建设全程给

| 阶段 | 手段 |
| --- | --- |
| **立项期** | 痛点访谈（找高频场景的同事聊，他们在什么环节骂娘）+ **种子用户共建** |
| **开发期** | 小步试用（每两周给种子用户用新版，即时纠偏）+ **迁移设计**（老数据一键导入、老习惯的快捷路径保留） |
| **上线期** | 培训陪跑（手把手教学 + 文档 + 答疑群）+ 示范场景（挑一个团队用出效果当样板） |

### 第三步：讲度量的牵引

上线后盯三个数，**哪个环节流失多就改哪**：

- **采纳率**（周活跃用户占比）
- **功能使用率**（哪些模块没人碰）
- **任务完成率**（用户在平台里走完全程的比例）

把平台当**产品运营**，而不是交付完事的工具。

### 第四步：讲激励机制的设计

- 让早期用户**有收益**（用平台省的时间看得见、用平台产生的数据用于汇报）
- **把平台嵌进流程**（CI 门禁必须走平台、提测报告平台自动出——流程依赖比自觉可靠）

推力和拉力一起用。

### 收尾：给心态

没人用不代表需求假——多数是「做了但没做到好用且没运营」。平台的成功公式是「**三分开发七分运营**」，愿意持续运营再立项。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 平台没人用是企业测开投入打水漂的头号形态——「会不会运营平台」是高级测开和普通测开的分界 |
| 过线标准 | 病因诊断 + 建设全程的预防手段 |
| 区分度 | 讲采纳率等功能度量、讲流程嵌入的推力设计的是有运营实战的 |
| 加分项 | 「三分开发七分运营」的产品意识 |
| 减分项 | 「做好了自然有人用」，对运营零认知，平台必死 |
