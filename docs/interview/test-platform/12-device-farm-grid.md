# 12｜UI 自动化平台怎么和设备资源打通？Selenium Grid 和设备农场怎么做？

> 开场先讲**资源层的架构**：Web 端 Selenium Grid（或 Playwright 的容器方案）做浏览器资源池；移动端设备农场（STF 或自建）管理真机池——**两端资源统一进平台的调度体系**，先给资源池化的大图。

## 回答思路

### 第一步：浏览器资源的管理（三件套）

1. **Grid 节点的容器化**（docker 起浏览器节点，按需扩缩）
2. **浏览器版本的矩阵管理**（多版本并存的节点标签，用例指定版本调度到对应节点）
3. **节点的健康检查**（僵尸节点的自动摘除）

### 第二步：讲移动端设备的管理

- 真机的接入（adb 远程连接或农场方案）
- **设备占用与排队**（用例要 iPhone 15——占用释放的调度）
- 设备的**分组标签**（机型、系统版本——兼容性矩阵的执行调度基础）
- 真机的物理运维（批量充电、稳定性监控）——**真机农场一半是软件一半是机房运维**，这个现实认知很加分

### 第三步：讲云真机的混合策略

自建满足**高频核心机型**、云真机平台（WeTest 这类）覆盖**长尾机型**——混合调度按机型需求自动路由，成本和覆盖的平衡。

### 收尾：讲执行的可观测

- 设备或节点的**实时状态看板**（谁在用、跑什么、排队几个）
- 执行过程的**远程观看**（浏览器执行的 VNC 直播、真机的实时屏幕）——**用户能看到自己的用例在跑，是信任感的来源**

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | UI 和 App 自动化的平台化难点全在资源层（浏览器和真机的池化调度）——考察基础设施的架构能力和资源运维的实操经验 |
| 过线标准 | 两端资源池的架构 + 占用调度机制 |
| 区分度 | 讲容器化版本矩阵、自建加云真机混合、远程观看体验的是真管过资源池的 |
| 加分项 | 真机农场「一半是机房运维」的现实认知 |
| 减分项 | 没想过资源池，用例在哪台机器跑听天由命——多任务一并发就互相干扰 |
