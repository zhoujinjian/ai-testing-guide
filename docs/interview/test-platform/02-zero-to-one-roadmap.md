# 02｜从 0 到 1 搭建一个测试平台，你会怎么规划？

> 开场先讲规划的方法论起点：**从痛点排序到 MVP**——先调研（团队时间都耗在哪：用例管理乱、回归执行慢、环境排队长），痛点按「**痛的程度 × 频率**」排序，第一个版本只解决第一痛点。MVP 思维是本题的第一得分点。

## 回答思路

### 第一步：给分阶段的路线图

| 阶段 | 周期 | 里程碑 |
| --- | --- | --- |
| **MVP** | 两三个月 | 单点工具跑通（比如接口自动化的在线执行），有**十个种子用户**真实使用 |
| **核心闭环** | 半年 | 补齐用例管理 + 执行 + 报告的链路，接入 CI |
| **平台化** | 一年 | 多团队、权限、数据隔离、度量看板 |

路线图的**颗粒度**体现规划能力。

### 第二步：讲技术上的起步决策

1. 技术栈选团队**最熟的**（不是最新的——平台的核心竞争力是贴合业务不是技术炫技）
2. **先单体后拆分**（用户量没到不用微服务）
3. **数据模型先想清楚**（用例和执行的数据结构是地基，改起来最贵）

### 第三步：讲运营从第一天开始

- **种子用户共建**：他们提需求你迭代，上线就是他们要的样子
- **使用数据埋点**：从第一天就知道功能有没有人用
- **迭代节奏公示**：让用户看到平台在长

运营意识是平台活下来的真正变量。

### 收尾：讲 0 到 1 的心法

**克制**（每期只做最痛的一件事）、**快**（小步快跑让用户尽快看到反馈）、**活**（宁可功能少但每个都被人用，也不要功能全但大半闲置）。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 测开平台方向的核心大题，等同功能测试的「怎么开展测试」——规划有没有阶段感和里程碑、有没有运营意识，一开口就分层 |
| 过线标准 | MVP 起步 + 三阶段路线图 |
| 区分度 | 讲痛点排序法、讲种子用户共建、讲第一天埋点的是真从 0 做过或深度思考过的 |
| 加分项 | 「克制、快、活」的三字心法这类可复用的方法论 |
| 减分项 | 一上来设计大而全的架构图（微服务、中台、全家桶）——0 到 1 阶段过度设计是经典陷阱 |
