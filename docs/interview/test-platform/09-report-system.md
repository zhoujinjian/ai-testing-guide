# 09｜报告体系怎么设计？结果展示、趋势、失败分析怎么做？

> 开场讲**单次报告的结构**——报告是平台价值的最终呈现层（老板看到的就是它），服务于「这次跑得怎么样、挂的为什么挂」两个即时问题。

## 回答思路

### 第一步：单次报告的结构

- **执行概览**：总数、通过率、耗时、环境信息
- **用例明细**：可下钻看每条的日志、断言差异、截图
- **失败聚焦**：失败的单独列表加首轮失败原因分类
- **原始产物**：日志文件、录屏、trace 的留存和下载

### 第二步：讲历史趋势的设计（从快照变电影）

- **跨次对比**：这次和上次的差异，**新增失败高亮**——回归判断的核心
- **指标趋势**：通过率、用例数、耗时的曲线（健康度随时间的变化）
- **基线对比**：和指定基线的 diff，发布决策用

### 第三步：讲失败分析的聚合（从记录变洞察）

- **失败原因归类**：环境、代码、用例自身——人工标注或 AI 辅助（呼应合集六 09 题）
- **flaky 用例榜**：不稳定用例的排名，治理清单
- **失败热点**：哪个模块失败最集中，风险地图

### 第四步：讲分受众的呈现

测试自己要明细、开发要失败原因和归属、管理层要趋势和结论——**一份报告三种视图**（或三种导出），受众意识是平台产品的软实力。

### 收尾：讲数据底层的设计

执行结果的**原始数据全量存**（明细可追溯）、**聚合指标预计算**（趋势查询不拖垮库）、报告的链接可分享（存档归档）——数据层设计决定报告功能的天花板。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 报告是用户每天打交道最多的界面——考察产品思维加数据设计的复合能力，报告做得好的平台采纳率翻倍 |
| 过线标准 | 单次结构 + 趋势 + 失败归类三层 |
| 区分度 | 讲新增失败高亮、flaky 榜、分受众视图的是深度运营过报告的 |
| 加分项 | 原始产物（录屏 trace）留存这类排障刚需的考虑 |
| 减分项 | 报告就是通过率数字加列表，没有趋势没有分析，价值层缺失 |
