# 15｜平台的价值怎么度量？怎么向管理层汇报？

> 开场给价值的**三个度量维度**——平台是持续投入的项目，每年都要证明自己值得存在。

## 回答思路

### 第一步：三个度量维度

| 维度 | 指标 |
| --- | --- |
| **使用规模** | 活跃用户、团队覆盖、日均执行任务数——平台的渗透率 |
| **效率替代** | 平台执行替代的人工工时（任务数 × 单次手工耗时的换算）——直接的降本账 |
| **质量贡献** | 平台门禁拦住的问题数、逃逸率的变化趋势——增值的质量账 |

### 第二步：讲度量的细节设计（口径的严谨度决定汇报的可信度）

- **替代工时的换算口径要保守**（用实测的手工耗时，不用用户报的，防虚高）
- **门禁拦截的定义要清晰**（拦的是真问题不是误报，统计有效拦截）
- **使用要区分深度**（登录看一眼和天天执行任务是两种使用——深度的口径才有意义）

### 第三步：讲向管理层汇报的方法（汇报是翻译）

- **讲投入产出**：建设维护的人力成本 vs 节省的成本加风险规避，算总账
- **讲趋势不讲快照**：采纳率的增长曲线比当月数字有力
- **讲业务语言**：「发布周期从两周到三天」比「执行了一万次任务」让管理层有感知

### 第四步：讲汇报的节奏

日常的**数据看板**（管理层随时可看，不用等汇报）→ 季度的**价值总结**（趋势加案例加下阶段规划）→ 立项式的**专项汇报**（要资源时讲清增量投入的预期回报）。

### 收尾：给一个诚实的认知

平台价值有一部分难以量化（流程规范化的隐性收益、质量信心的心理收益）——**能量化的讲数字，不能量化的讲案例**。全靠编数字的汇报一旦被拆穿，平台和人的信用一起完蛋。

## 考察重点

| 维度 | 说明 |
| --- | --- |
| 企业动机 | 不会汇报的平台 owner 拿不到持续资源——考察「技术价值向管理价值翻译」的能力 |
| 过线标准 | 三维度度量 + 保守口径的设计 + 管理层语言的汇报 |
| 区分度 | 讲口径防虚高、讲趋势不讲快照、讲不可量化的诚实处理的是汇报老手 |
| 加分项 | 日常看板加季度总结加专项汇报的分层节奏 |
| 减分项 | 汇报全靠形容词（「大幅提效」「广受好评」）没有数字，或数字夸张经不起追问 |
