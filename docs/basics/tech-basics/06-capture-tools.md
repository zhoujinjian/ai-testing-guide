# 06｜抓包工具入门：Fiddler 与 Charles

> 核心要点：抓包工具是**架在你设备与服务器之间的检查站**，页面上每个动作背后发了什么请求、服务器回了什么，全部摊开给你看。测试用它干三件事：**定位 bug 在前端还是后端、提取接口信息给 Postman 重发、模拟弱网等特殊网络**。

## 打个比方

机场的**安检 X 光机**。

旅客（数据请求）排队过安检，你站在屏幕前，每个包裹里装了什么——充电宝、水杯、一件外套——看得清清楚楚。平时你只看到"旅客进去了、旅客出来了"（页面点了、页面变了），中间包裹里到底装了什么，你不知道。抓包工具就是那道**传送带**：请求从你设备发出前先经过它，它拍张"X 光片"记下来，再放行给服务器；服务器回来的响应也照样过一遍。

测试的很多困惑，有了这张 X 光片就消失了："按钮点了没反应"——是包裹根本没寄出去（前端没发请求），还是寄出去了被拒收（后端返回错误）？安检屏上一眼见分晓。

## 展开讲讲

### 先分清两位主角

| 对比 | Fiddler | Charles |
| --- | --- | --- |
| 平台 | Windows 体验最佳，Mac 可用 | Windows / Mac 都顺 |
| 价格 | 免费 | 付费（有免费试用版，每小时断一次） |
| 顺手功能 | Composer 重发、断点改参 | Repeat 重发、Map Local 映射本地文件、**弱网模拟**很方便 |
| 怎么选 | Windows 机器首选 | Mac 机器、或需要弱网/Map Local 时首选 |

两个工具原理一模一样：在本机开一个**代理**（可理解为所有流量先绕到它这里过一遍安检），界面和信息结构也大同小异，**学会一个另一个半天上手**。

### 带着任务学：第一次打开干什么

别研究菜单，直接完成四个任务：

**任务一：让它能看到 HTTPS。** 现在的网站几乎全是 HTTPS，不装证书的话抓到的全是加密乱码 `CONNECT xxx:443`。以 Charles 为例：Help → SSL Proxying → Install Charles Root Certificate，按提示信任证书；再 Proxy → SSL Proxying Settings 勾选 Enable。Fiddler 在 Tools → Options → HTTPS 里勾 Decrypt HTTPS。装证书只在本机代理场景有效，**别在公司外网随手信任来路不明的证书**。

**任务二：抓一条登录请求。** 打开目标网站 → 工具里清一下列表 → 执行登录 → 列表里找那条 login。认它的三个特征：方法 POST、URL 带 login、状态码 200。

**任务三：看懂一条请求的三块信息。** 点开它：**Headers**（请求头/响应头，看 Cookie、Content-Type）、**Body/JSON**（请求体里的账号密码、响应体里的返回数据）、**状态码**。F12 的 Network 面板结构与此完全对应——两个地方看的是同一样东西。

**任务四：重发一次改个参数。** 选中那条登录请求：Charles 点 Repeat 直接原样重发；Fiddler 拖进 Composer，把密码改错一位再 Execute——观察返回变成 code:1001 密码错误。**到这一步你已经在做接口测试了**，和 Postman 干的是同一件事（第 07 篇）。

### 测试工作里它出场的高频时刻

| 场景 | 动作 |
| --- | --- |
| 页面报错，判断前后端谁的锅 | 找到对应请求：**请求没发出发错** → 前端；**请求对了返回错** → 后端 |
| 页面接口没文档 | 抓一条请求，方法、URL、参数、返回全套抄下来，Postman 里复刻 |
| 手机 App 抓包 | 手机 Wi-Fi 代理指向电脑 IP:8888，手机装证书后同样透明 |
| App 客户端说"服务器问题" | 拿到确切的状态码和响应体再转给后端，别只传一句话 |
| 模拟弱网 | Charles → Proxy → Throttle Settings，限成 3G 网速看加载与超时表现 |

还有一个进阶动作值得知道：**断点改参**（Charles 的 Breakpoints、Fiddler 的 bpu 命令）——把请求拦在半路，改完参数再放行，等于在"看"和"重发"之间加了一道现场编辑，联调时改参数特别顺手。初学阶段先掌握到重发为止，断点等基础用熟了再上。

## 举个例子

测试电商 H5："我的优惠券"页偶尔空白，前端说"后端没给数据"，后端说"我这边没报错"。你打开 Charles 复现一次：列表里立刻看到 `GET /api/coupon/list` 状态码 **200**，点开响应体，`data` 数组是**空的**——服务器确实回话了，但数据是空的。再抓一次正常账号的请求对比：同样 200，data 里有 3 张券。把两条响应体截图贴到群里：问题收敛为"这个账号查不到券"，后端顺着账号一查，是该账号的券在另一张表里没同步——**一张 X 光片，结束了三天的拉扯**。这就是抓包工具在测试手里的价值：用证据说话，而不是用转述传话。

## 新手常见误区

| 误区 | 实际情况 |
| --- | --- |
| 抓包是"黑客行为" | 抓的是**自己设备自己账号**的流量，测试日常工作，与攻击他人是两回事 |
| 工具一开就全能看到 | HTTPS 需装证书并启用解密，装错一步看到的全是乱码或 Tunnel |
| 抓包和 F12 是两套知识 | 结构完全对应（请求头/体/响应），学会一个另一个直接迁移 |
| 抓到 200 就是没问题 | 200 只代表通信成功，data 为空、业务 code 报错都藏在响应体里 |
| 手机抓不了就放弃 | 手机设代理 + 装证书是标准动作，App 测试必备技能，一次配好处处能用 |
| 证书装完永远不撤 | 只该在测试设备上信任测试证书，用完可移除，别带进日常上网环境 |

## 上手建议

1. **今天就装一个**：Windows 装 Fiddler、Mac 装 Charles，跟完上面四个任务，比看十篇教程都管用
2. **把证书流程做成小抄**：电脑版、手机版各记三步，下次新设备配代理不用现查
3. **养成"先抓包再提单"的习惯**：页面类 bug 提单前先抓包看一眼那条请求——状态码和响应体写进单子，前后端都不用来回问你
4. **用 Repeat 做重复提交测试**：对下单、领券类接口连 Repeat 十次，防重没做马上现形
5. **试一次弱网模拟**：Charles 限速到 3G，打开你们的 App 看哪些页面转圈不出、按钮连点会不会重复下单
