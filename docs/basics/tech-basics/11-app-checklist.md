# 11｜App 测试要点与专项

> 核心要点：App 功能测起来和 Web 差不多，但它**多出一整层"环境对抗"**——设备适配、系统版本、来电中断、弱网、耗电、安装升级。这些**专项**才是 App 测试的分水岭：功能都对，来电回来白屏、电梯里转圈、挂后台一夜没电，照样是事故。

## 打个比方

**提新车验车**。

看配置表（功能测试）只能确认"该有的都有"，但车好不好开，得上路验：**踩一脚急刹**看看会不会点头（中断恢复——来电、锁屏后回来状态还在不在）；**故意走段烂路**听有没有异响（弱网——网络差时是优雅提示还是白屏）；**看看油耗**（耗电流量）；**不同身高的人轮流坐**（机型兼容——大屏小屏、刘海屏有没有遮挡）；**旧车置换升级**时里程和油量数据有没有丢（覆盖安装、跨版本升级）。

App 就是那台车：功能清单过得再顺，专项不拉出来遛一遛，交付到用户手里还是会出事。

## 展开讲讲

### App 测试维度大表

| 维度 | 检查点 |
| --- | --- |
| **功能** | 核心流程真机走通；页面间数据传递；前后台切换回来状态保持；杀进程重启后的恢复 |
| **UI 适配** | 主流分辨率不错位；**刘海屏/挖孔屏**不被状态栏遮挡；横竖屏切换布局正确；深色模式下文字可读；系统字体放大 200% 不破版 |
| **兼容** | iOS 与安卓主流系统版本；高中低端机型流畅度差异；华为、小米、OPPO、vivo 等厂商定制系统表现一致 |
| **中断** | 来电、短信、闹钟、锁屏、切后台、弹横幅通知、低电量弹窗——打断后回来，页面状态和数据对不对 |
| **弱网与无网** | 弱网加载有提示、按钮防重；无网有兜底页；网络恢复后能续上；**电梯、地铁、地库**真实切换场景 |
| **耗电与流量** | 后台挂 30 分钟耗电占比是否异常；前台连用是否发烫；一次核心流程流量消耗与场景匹配 |
| **安装卸载升级** | 全新安装；**覆盖安装**用户数据保留；卸载重装数据清空且需重新登录；低版本跨版本升级不丢数据 |
| **权限** | 首次启动权限弹窗时机合理；**拒绝授权**后功能有引导而非闪退；系统设置里开开关关权限即时生效 |
| **推送与离线** | 杀进程后仍能收到推送；点推送直达正确落地页；离线时浏览过的内容有本地缓存 |

### 五大专项的具体操作方法

**弱网**：两条路——电脑装 Charles，手机代理指向它，Proxy → Throttle Settings 勾选限速，选 3G 档（约 400kbps、400ms 延迟），全 App 在慢网下过一遍主流程；真实现场补充：拿着手机进电梯、地铁跑一遍，专测**网络切换瞬间**（Wi-Fi 转 4G）的操作表现。

**中断 call**：准备另一台手机当"来电方"。重点测**业务进行中被呼叫**：支付弹密码框时来电、播放视频时来电、填了一半表单时来电；再配闹钟（设 2 分钟后响）、锁屏再解锁、下拉一条横幅通知——每种打断回来后，核对**页面还在、输入还在、状态没乱**。

**耗电**：充满电拔线 → App 挂后台 30 分钟 → 系统设置→电池，看它在耗电排行里的占比（正常应接近零，排行第一就是后台没安分）；前台连续使用 20 分钟，摸机身温度、看掉电速度。安卓可进一步用 `adb shell dumpsys batterystats` 拿详细统计。

**兼容**：整理公司用户的**Top 机型清单**（后台统计或问产品拿），高、中、低三档各留真机；买不到的机型上云真机平台（WeTest、TestIn 一类）租用，重点跑安装、启动、支付、推送四个场景。

**安装卸载升级**：固定四个动作——①全新安装直接开测；②在旧版本上覆盖安装新包，验证**登录态、本地数据、设置项全部保留**；③卸载重装，验证数据清空、必须重新登录；④拿一个落后好几个版本的包（如 1.0）直接升到最新，验证数据迁移不丢——这一步最容易炸，老用户就是这么流失的。

## 举个例子

电商 App 发版前专项走一轮：小米中端机上覆盖安装 2.3.1 → 2.4.0，登录态保留、购物车里 3 件商品还在——通过；Charles 限速 3G 后领优惠券，按钮转圈 4 秒后成功，但**连点两次领了两张**（防重没做，bug）；支付密码框弹出时来电，接完电话回来发现**支付页白屏**（页面重建没恢复状态，bug）；后台挂 30 分钟，耗电排行第一，报给开发查出定位服务没停（bug）；1.0 版本直升 2.4.0，用户收货地址全在——通过。功能用例一条没跑，三个专项 bug 已经到手——**专项的性价比就在这**。

## 新手常见误区

| 误区 | 实际情况 |
| --- | --- |
| App 测试 = Web 测试换个屏幕 | 环境对抗（中断/弱网/耗电/适配）是 App 独有的整层工作 |
| 只在自己那一台手机上测 | 你的手机只是千万用户之一，高中低端 + 厂商定制都得抽测 |
| 中断测试随手点两下 | 每种中断要单独成用例、记录"打断时所处的页面"，否则复现都说不清 |
| 耗电流量归开发管，测不了 | 后台挂机对比、机身温度、排行占比，都是测试用真机就能做的量化动作 |
| 覆盖安装不会丢东西，不用测 | 数据迁移恰恰是升级事故高发区，跨版本升级必测 |
| 弱网就是"页面转圈慢一点" | 弱网下重复提交、超时后状态错乱、断点续传，才是要抓的真问题 |

## 上手建议

1. **领两台测试机**：一台高配一台低配，覆盖不了的两头，中间机型靠云真机补
2. **本周配好弱网环境**：电脑装 Charles、手机设代理限速，配一次用一年（配法见第 06 篇）
3. **把五大专项做成固定用例集**：每条写清"前置状态 + 操作 + 预期"，发版前整轮跑，不靠临场想起
4. **拿到公司的 Top 机型清单**：问产品或运营要用户机型统计，按占比定兼容测试范围
5. **中断测试用第二台手机**：没有旧手机就用同事的，来电是唯一没法完全模拟的中断
