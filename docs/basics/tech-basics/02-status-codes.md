# 02｜HTTP 状态码：200、301、404、500 都是什么

> 核心要点：状态码是服务器对每个请求回的**一句话结论**，写在响应的第一行。记住四大类就够用：**2xx 成功、3xx 跳转、4xx 客户端错了、5xx 服务器错了**——先看首位数字定方向，再看具体码定位。

## 打个比方

状态码就像**银行柜员的回复**。

你递单子办业务，柜员总会先给你一句话：**"办好了"**（2xx，业务成功）；**"这个业务去 3 号窗口办"**（3xx，去别处，跟着指的路走就行）；**"你这单子填错了、没带身份证、这个业务我们不办"**（4xx，问题在你这边）；**"系统升级中，柜台办不了"**（5xx，问题在银行这边）。

这个比喻里最值钱的是**先分清是谁的责任**：4xx 是"你的单子有问题"，5xx 是"银行自己出了问题"。测试提 bug 时这个区分就是定责的第一依据——404 多半是请求地址错了，500 则要立刻喊后端去看日志。

## 展开讲讲

### 四大家族总览

| 大类 | 一句话 | 测试直觉 |
| --- | --- | --- |
| 2xx 成功 | 服务器收到、看懂、办成了 | 通信层面没毛病 |
| 3xx 跳转 | 资源搬家了，去新地址拿 | 跟着走，但要警惕循环跳转 |
| 4xx 客户端错误 | 请求本身有问题 | 先查自己：地址、参数、凭证、权限 |
| 5xx 服务器错误 | 服务器内部出错 | 基本可以喊后端了 |

### 高频码逐个说

| 码 | 含义 | 测试什么时候会碰到 |
| --- | --- | --- |
| 200 | 成功 | 正常用例的标配返回 |
| 201 | 创建成功 | 新建订单、注册成功这类"生成新资源"的接口 |
| 204 | 成功但无内容 | 删除接口常返回它，响应体是空的，别当成 bug |
| 301 | 永久跳转 | 老域名迁新域名、http 整体转 https |
| 302 | 临时跳转 | 未登录访问个人中心被踢回登录页，登录后回跳 |
| 304 | 缓存未变 | 二次刷新页面时大量出现，说明浏览器用了缓存 |
| 400 | 请求参数错误 | 传了格式错的 JSON、缺必填字段，多发生在自己调接口时 |
| 401 | 未认证 | 没登录就调接口、token 过期——登录态 bug 的头号特征 |
| 403 | 已认证但无权限 | 普通账号调管理员接口，越权测试的预期返回 |
| 404 | 地址不存在 | 前端把路径拼错、接口已下线没同步 |
| 405 | 方法不允许 | 接口只收 POST 你发了 GET，前后端联调常见 |
| 429 | 请求太频繁 | 触发限流：秒杀连点、60 秒内重发短信验证码 |
| 500 | 服务器内部错误 | 后端代码抛异常，提 bug 附上请求体和时间段 |
| 502 | 网关错误 | 后端服务挂了或没起来，环境问题的常客 |
| 503 | 服务不可用 | 服务器过载，或正在发布重启 |
| 504 | 网关超时 | 后端处理太慢（慢 SQL、下游卡住），压测时常客 |

不用背全表，先记住三对易混的：**401 和 403**（没登录 vs 没权限）、**500 和 502**（程序错了 vs 服务没了）、**502 和 504**（后端回了个错误 vs 后端压根没回）。

### 状态码在哪里看

三个地方都能看到它：浏览器按 F12 → Network 面板的 **Status 列**，一列看尽整页所有请求的成败；Postman 里 Send 之后返回区右上角的大号数字；命令行用 `curl -i` 请求，返回的第一行就是：

```bash
curl -i https://httpbin.org/get
# 返回第一行 HTTP/1.1 200 OK，200 就是状态码
```

测试环境排查问题时，**先扫 Status 列有没有标红的非 2xx 行**，往往比从页面报错倒着找快得多——页面只给你一句"系统繁忙"，Status 列直接告诉你哪条请求、什么码。

### 新手必知的区分：HTTP 状态码 vs 业务 code

很多系统通信上是 200，响应体里却有自己的业务码：`{"code":1001,"msg":"密码错误"}`。**200 只代表"服务器回话了"，不代表"业务办成了"。**接口测试的断言通常两层都要做：既看 HTTP 状态码，也看业务 code——两层各管各的，谁也替代不了谁。

## 举个例子

测电商 App 的"修改收货地址"功能，四种返回对应四条完全不同的排障路径：

1. **200 + code:0**：通信和业务都正常，继续校验响应体里的地址对不对
2. **401**：你先退出登录再点修改，被正确拦住了；但如果**刚登录完就 401**，那就是 bug——抓包看请求头里 Cookie 或 token 带没带
3. **400 + "areaId 不能为空"**：前端没传地区字段，典型的前后端字段没对齐，联调问题
4. **500**：地址填了 500 个字符，把后端数据库字段撑出了异常——这是**边界值测出来的后端 bug**，提单时把请求体原样贴上

同一条接口，四种状态码指向四个不同的去处。这就是为什么 bug 单里"接口返回什么码"是必填信息——它几乎直接决定了单子该派给谁。

## 新手常见误区

| 误区 | 实际情况 |
| --- | --- |
| 200 就等于测试通过 | 还要看响应体：业务 code、数据内容、字段正确性 |
| 404 一定是 bug | 也可能是接口本来就没上线、环境没部署、路径前缀拼错 |
| 把 4xx 都当服务端问题 | 4xx 开头就是"客户端的锅"，先检查自己的请求再喊后端 |
| 把 304 当异常 | 缓存命中是正常机制，只有"改了数据页面没变"时才怀疑缓存 |
| 报 5xx 只写"系统崩了" | 附上 URL、请求体、时间点、traceId，后端才能去日志里定位 |
| 想把几十个状态码全背下来 | 高频的二十来个够用，冷门的遇到了再查，不用硬背 |

## 上手建议

1. **F12 里数状态码**：打开常用网站的 Network 面板，按 Status 列筛 4xx、5xx，看看哪些是真异常、哪些是正常拦截
2. **给自己定三个条件反射**：看到 401 想登录态，看到 403 想权限，看到 500 想后端日志，三秒定方向
3. **越权用例拿 403 当断言**：普通用户调管理员接口，预期 403；返回 200 反而是安全漏洞
4. **限流场景盯 429**：验证码、秒杀类功能连点几次，看会不会 429、提示文案友不友好
5. **bug 单里带上状态码**：从今天起标题写清"xx 接口返回 500"，比"页面报错了"信息量大十倍
