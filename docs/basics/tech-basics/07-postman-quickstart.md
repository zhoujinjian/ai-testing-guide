# 07｜Postman 上手：发第一个请求

> 核心要点：Postman 是**直接对后端发 HTTP 请求的工作台**——不等前端页面、不用写代码，填上 URL 和参数点 Send 就能拿到返回。它解决的是一件事：**让测试能亲手构造任意请求去考后端**，并且把这些请求沉淀成可复跑的用例集。

## 打个比方

**驾校的教练车**。

想学开车，不必等自己买车（前端页面开发完）才上手——教练车（Postman）把开车的每个动作**拆出来单练**：方向盘、油门、刹车都直接暴露在你面前，想练哪个练哪个；场地随便进（测试环境、预发环境切换）；压线了当场告诉你（断言结果）；练熟的动作录成流程（集合），下次照着跑一遍就行。

它和"直接上路"（在页面上点）的区别：页面上你只能按产品设计的路径走，而 Postman 里**方向盘随便打**——参数想填什么填什么，正是接口测试要的自由度。抓包工具（第 06 篇）是"看别人开车"，Postman 是"自己坐上驾驶座"。

## 展开讲讲

### 装哪个、第一次打开干什么

官网 postman.com 下载桌面版，注册个免费账号。第一次打开别研究菜单，按这条线走（十分钟内能跑完）：

1. **建集合（Collection）**：左侧 New → Collection，起名"商城项目测试"。集合 = 用例文件夹，后面所有请求都往里放
2. **建请求**：New → HTTP Request，看到那个熟悉的 GET 下拉框和 URL 输入框了吗——这就是驾驶座
3. **发第一条 GET**：找一个公开接口练手，URL 填 `https://httpbin.org/get`，点 **Send**，下半屏跳出 JSON 返回——恭喜，第一条请求发出去了

### 发一条真实接口：从 GET 到带登录态的 POST

拿电商登录接口练完整的四步：

**第一步，填基本信息**：方法选 POST，URL 填 `https://test-api.mall.com/api/login`。

**第二步，填请求体**：Body → raw → JSON（右侧下拉别选错），写入：

```json
{
  "username": "test001",
  "password": "Aa123456"
}
```

**第三步，看返回**：Send 之后下半屏出现状态码 200 和响应体，里面通常有 token——登录态的凭证，来历见第 04 篇。

**第四步，让其他请求自动带上它**：在登录请求的 Scripts（旧版叫 Tests）页签写两行，把 token 存进变量：

```javascript
const data = pm.response.json();
pm.environment.set("token", data.data.token);
```

之后所有需要登录的请求，只在 Headers 加一行 `Authorization: Bearer {{token}}`——**双花括号**会在发送时自动替换成变量值。一次配置，整个集合共用。

### 两件让 Postman 从"工具"变"用例"的事

**加断言**：光看返回不算测试，要让 Postman 自己判卷。Scripts 页签里：

```javascript
pm.test("状态码是200", () => pm.response.to.have.status(200));
pm.test("业务code为0", () => pm.response.json().code === 0);
```

Send 之后 Test Results 区显示绿勾或红叉——**绿勾红叉，就是通过失败**，这才是一条用例。

**配环境变量**：右上角 Environment → 新建"test 环境"，把 baseURL 存成变量 `{{baseURL}}`；再建一个"staging 环境"同样叫 baseURL。之后所有请求 URL 写 `{{baseURL}}/api/login`，**切换环境 = 一键换环境**，同一套用例两个环境复跑，回归时省一半力气。免费版对个人学习完全够用；团队想在多人之间共享集合，登录同一账号即可同步，这也是很多小团队管理接口用例的起步方案。

### 五个立刻提升手感的小动作

1. **Ctrl + Enter 发送**：不用挪鼠标去找 Send 按钮，双手不离键盘
2. **给请求改好名字**：默认都叫 New Request，改成"领券-重复领取"，集合才像一份用例集
3. **Copy as cURL**：右键请求 → Copy → cURL，贴给开发就能完整复现，bug 单里比截图好使得多
4. **History 面板翻旧账**：最近发过的请求全在，忘了保存时先翻它，能捞回不少
5. **描述栏写备注**：每个请求的 Description 里贴上接口文档链接和注意点，别人接手不用来回问

另外记得**改完参数随手 Ctrl + S**：请求的修改不会自动保存，忘了存，下次打开还是旧参数，莫名其妙"复现不了"多半是这个原因。

## 举个例子

提测的电商项目改了"领优惠券"接口，页面还要三天。你按这个流程把接口测试提前做掉：

1. 开发给的接口文档写着 `POST /api/coupon/receive`，参数 couponId。你在"商城项目测试"集合里新建请求，Body 填 `{"couponId": "C200"}`，Headers 带上 `{{token}}`
2. Send：200 + code:0，通过；再在 Scripts 里加上面两条断言
3. 复制这个请求成 4 份，分别改参数：不存在的券 `C999`、已下架的 `C301`、空值、再领一次已领过的 `C200`——第 4 份果然又发了一张券，**后端没做防重，bug 提走**
4. 版本末期回归：右键集合 → Run collection，4 条请求带断言自动跑完，Test Results 一屏绿勾

从"手动点一次"到"一键回归一个集合"，这就是 Postman 在测试工作流里的位置——手工接口测试的主力，也是将来过渡到接口自动化（路线第 6 章的 pytest + requests）前最好的练兵场。

## 新手常见误区

| 误区 | 实际情况 |
| --- | --- |
| 把 Postman 当"测接口的全部" | 它只负责**发请求、看返回、做断言**，用什么参数组合是设计问题，工具替代不了 |
| 每条请求手抄 token | 用变量 `{{token}}` 一次配置全集合复用，手抄既累又容易抄错 |
| 只看响应体，不加断言 | 没断言的请求只是"手动看一眼"，跑集合时无法自动判卷 |
| Body 选成 form-data 发 JSON | raw + JSON 才对，选错格式后端直接 400，新手第一天最常踩 |
| 请求散落不建集合 | 散请求没法批量重跑，回归时一条条手动发等于没积累 |
| 断言只写状态码 200 | 还要断业务 code 和关键字段，200 + code:1001 的失败会漏网 |

## 上手建议

1. **今天就发第一条请求**：装好 Postman，先请求 `https://httpbin.org/get` 拿到返回，把恐惧感先消掉
2. **拿自己项目的登录接口练全套**：建集合 → 发 POST → 存 token 变量 → 下一条请求带 `{{token}}`，这四步是每天都要用的肌肉记忆
3. **每条请求都补两条断言**：状态码 + 业务 code，从第一条就养成，别等做自动化才想起判卷
4. **配好 test / staging 两套环境**：baseURL 做成变量，本周就把切换环境的动作练熟
5. **按功能建子文件夹归置请求**：集合下按"登录""订单""优惠券"分目录，下个版本直接复用整组
