# 10｜安全测试入门：测试要懂的安全常识

> 核心要点：功能测试顺手就能发现的安全问题集中在四类——**SQL 注入、XSS、越权、敏感信息泄露**。你不需要懂攻击技术，需要的是**知道它们是什么、在授权范围内怎么检查、发现了怎么报告**。纪律红线一条：只在测试环境和授权范围内动手。

## 打个比方

小区**门禁保安**的工作不是研究怎么撬锁——那是 locksmith 和小偷的事。保安的日常是四件事：

检查**门禁卡会不会被冒用**（有人拿一张卡片刷开了三栋楼的门）；看**公告栏有没有被人贴小广告**（表面是公告栏，被人塞进了别的东西）；查**有没有人拿着别人的房卡开别人家的门**（卡是真卡，门不是他家的门）；巡**监控室屏幕上是不是拍着住户的密码本**（本不该被看到的东西摆在明处）。

保安发现问题就上报物业，不会自己破门取证。功能测试工程师之于软件安全，就是这个角色：**用常识发现可疑迹象，交给专业的人处理**。专业渗透测试是保安队之外的反扒专家，那是另一个工种（职业方向见[测试行业岗位地图](../concepts/11-career-map.md)）。

## 展开讲讲

### 四类高频安全问题，人话版

**1. SQL 注入**：输入框本该填"张三"，有人填了一段特殊拼写的文本，让后端数据库把它误当成指令执行，交出了不该给的数据。**怎么发现（常识级）**：在输入框输入含引号、百分号这类特殊字符的内容提交，看系统是正常处理、给出友好报错，还是弹出露骨的数据库报错信息——报错页直接把 SQL 语句原样吐出来，基本可以断定有问题。**注意**：发现迹象就停手提单，不继续验证能捞到什么数据，那是安全团队授权后的事。

**2. XSS（跨站脚本）**：把一段脚本内容"贴"进页面——比如把昵称改成脚本片段——其他用户打开他的主页时，这段内容被浏览器当成代码执行了。**怎么发现**：在输入框输入一对尖括号包着的英文单词（如 `<test>`）保存，刷新页面看它是**原样显示成文本**（安全）还是**消失或变形**（可疑——被当成代码解析了）。提示"昵称含非法字符"说明前端拦了；再用抓包直接调接口重发一次，确认后端也拦了才算过。

**3. 越权**：拿合法身份，动了不属于自己的数据。分两种：**水平越权**——同是普通用户，A 改了地址栏里的订单号就能看 B 的订单；**垂直越权**——普通用户直接请求管理员才有的接口，居然成功了。**怎么发现**：备两个测试账号，A 账号把请求里的订单号 / 用户 ID 换成 B 账号的发出去，看数据返回不返回；用普通账号的登录态调一个管理接口，看拦不拦。这是功能测试**最该顺手做**的一项，因为它根本不需要攻击技术。

**4. 敏感信息泄露**：不该给的数据送到了不该到的地方。**怎么发现**：抓包逐个看接口响应——页面上手机号显示 138\*\*\*\*8000，响应里却是完整手机号（多余字段）；密码在传输或存储里是明文；日志文件里打印了用户密码；报错页把内部路径、框架版本暴露无遗。

| 问题 | 人话解释 | 常识级检查 | 报告要点 |
| --- | --- | --- | --- |
| SQL 注入 | 输入被数据库误当指令执行 | 特殊字符提交看报错是否露骨 | 输入内容 + 报错截图，标注"疑似" |
| XSS | 恶意内容被浏览器当代码执行 | 尖括号内容保存后看是否原样显示 | 输入内容 + 页面表现 |
| 越权 | 合法身份动了别人的数据 | 双账号换 ID 互查、普通号调管理接口 | 两个账号 + 请求响应截图 |
| 敏感信息泄露 | 数据给了不该给的地方 | 抓包看响应字段、翻日志、看报错页 | 泄露字段清单 + 抓包截图 |

### 红线：授权与纪律

三条纪律刻在脑子里：**只在测试环境做**，生产环境不做任何探测性请求——哪怕"只是想验证一下"；**发现即止**，不做扩大验证（不尝试能捞多少数据、能渗透到哪一层）；**第一时间上报**，敏感信息泄露和越权是事故级问题，走紧急流程。安全测试的资格来自授权，没有授权的探测本身就是违规。

### 功能测试顺手做的安全四件套

每个版本花半小时过一遍：**密码传输存储是否加密**（和开发确认方案）、**接口是否校验数据归属**（越权抽查两个账号）、**响应字段是否最小化**（页面不展示的不该返回）、**报错信息是否克制**（不暴露内部细节）。

## 举个例子

测试环境测"订单详情"页，功能测完顺手做安全四件套：

- **越权**：用账号 A（自己下单 order_id=10001）抓包，把 ID 改成账号 B 的 10002 重发——**数据返回了**。水平越权实锤：接口没校验"这单是不是你的"。提单：建议后端按登录态校验数据归属
- **泄露**：翻这个接口的完整响应，发现除了页面展示的字段，还返回了完整手机号、真实姓名、收货门牌号——页面明明打码了，接口原样全给。提单：建议响应字段最小化，只返回页面需要的
- **报错**：把 order_id 改成一个字母，响应里吐出一整段后端异常堆栈，包含框架版本和内部路径。提单：建议统一错误处理，对外只回"参数错误"
- **XSS 抽查**：备注栏输入 `<test>` 保存——列表页原样显示 `<test>` 文本，安全；抓包直接调接口再发一次，后端也原样存储原样转义显示，通过

三条 bug 单都带双账号信息、请求响应截图，严重程度标高（涉及用户隐私）。开发当天修完——**越权和泄露这类问题，修复成本通常很低（加一行归属校验、裁几个字段），晚发现的代价却很高**。

## 新手常见误区

| 误区 | 实际情况 |
| --- | --- |
| 安全测试是安全团队的事，与我无关 | 越权和信息泄露恰恰是功能测试顺手就能发现的；最常漏的就是"页面打码、接口裸奔" |
| 做安全测试必须会攻击技术 | 常识级检查 + 授权纪律，就是新手能贡献的安全价值 |
| 生产环境试一下才知道真有没有问题 | 未经授权碰生产是红线，一律禁止，没有例外 |
| 前端拦截了就算安全 | 前端限制对抓包工具完全无效；后端必须自己校验，前后端各拦一遍才作数 |
| 报安全问题太较真会得罪开发 | 隐私泄露是事故级问题，早上报早止损，开发比你更怕它上线后才被发现 |

## 上手建议

1. 给自己负责的模块做一次越权抽查：备 A、B 两个账号，A 改 ID 看 B 的数据，翻一遍核心接口
2. 抓包逐个看响应字段，列一张"页面展示 vs 接口返回"对照表，多余字段全部提单（抓包入门见[抓包工具入门](../tech-basics/06-capture-tools.md)）
3. 和开发确认密码的传输与存储方案：是 HTTPS 吗、存的是明文还是加盐哈希——确认不了就把问题带给你导师
4. 输入框过一遍特殊字符：引号、尖括号、百分号，看报错信息是否露骨
5. 把安全四件套（密码、归属、字段、报错）加进用例模板，每个版本固定过一遍
