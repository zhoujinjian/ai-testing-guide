# 09｜兼容性测试：浏览器、机型、分辨率、版本

> 核心要点：兼容性测试验证的是**同一个软件在不同环境里表现是否一致**——不同浏览器、机型、分辨率、系统版本、网络环境。环境组合成千上万测不完，**用用户数据选范围**是第一原则，云真机平台是主力武器。

## 打个比方

出国旅行带的**转换插头**：你的充电器本身没坏，但插进不同国家的插座就出各种状况——英标三脚、欧标两圆孔、美标扁脚，规格全不一样。插座还分新旧：老酒店插座松，插上去接触不良；新酒店电压稳。你得列一张"我要去哪几个国家、住什么酒店"的清单，按清单配转换头。

软件一样：产品本身测得没问题，换一台两年前的安卓机、换一个低版本浏览器内核，按钮错位、图片不显示、页面卡死。**兼容性测试就是出发前把"要去哪些国家"列成清单**——这份清单在行业里叫**兼容矩阵**。全部国家都配插头（全量机型都测）不现实，商务出行只去三个城市，就只配三种插头（按用户数据裁剪范围）。

## 展开讲讲

### 兼容什么：四个坐标

| 端 | 兼容对象 | 典型问题 |
| --- | --- | --- |
| Web | 浏览器及版本（Chrome / Edge / Safari / Firefox） | 新 CSS 语法老浏览器不认，样式崩 |
| Web | 分辨率、缩放比例 | 1366×768 笔记本上表格挤出屏幕 |
| Web | 微信 / 企业微信内置浏览器 | 分享卡片调不起、支付面板被拦截 |
| App | 机型（品牌 × 屏幕） | 曲面屏边缘手势误触、刘海屏遮标题 |
| App | 系统版本（iOS / Android 各版本） | 只适配到 Android 12，13 上通知不弹 |
| App | 厂商 ROM（国产定制系统） | 国产系统杀后台狠，推送收不到 |
| 通用 | 网络环境（弱网、切换） | 电梯里断网后页面白屏不恢复 |

典型症状清单也值得背几句：**布局错位、元素重叠、文字溢出、按钮点不动、图片裂图、滚动卡顿、弹窗被状态栏遮住**——提兼容 bug 时，症状描述得越具体，开发定位越快。

### 怎么选范围：数据说话

机型浏览器组合成千上万，全测不可能。范围用三个信息源圈定：

- **用户数据**（第一原则）：埋点统计用户设备 TOP 10，覆盖住七成用户的机型必须全过
- **产品定位**：给老年人用的 App 加测大字号、低端机；企业内网系统加测 Edge 兼容模式
- **历史易碎区**：上个版本在哪类机型崩过，这类进常备清单

矩阵搭法最常用**高中低三档**：高端旗舰一台、主流中端两台、两年前低端机一台，再加分辨率两极（最小 360×640 和最大 2K / 4K）各验一遍。低端机尤其不能省——**历史兼容 bug 的一半来自低配机型**：内存小、CPU 慢、系统旧，问题全在这现形。

### 怎么测：真机、模拟器、云真机

| 手段 | 优点 | 缺点 |
| --- | --- | --- |
| 本地真机 | 最真实 | 买不起也管不过来，量小 |
| 模拟器 | 免费快速 | 复现不了厂商 ROM 差异和真机性能，不能作为通过依据 |
| 云真机平台 | 几百台真机远程租用，主流方案 | 按时长计费，排队高峰要等 |

弱网也是兼容性的一部分：用工具把网速限到 200ms 延迟、20% 丢包，看页面是优雅降级（提示"网络不给力"）还是直接白屏。

### 最容易被漏的一格：版本向后兼容

矩阵里四个坐标都好理解，最容易漏的是**新旧版本之间的兼容**：服务端接口升级后，线上还在跑的**老版本 App** 还能不能正常用？新接口改了字段结构、新版客户端适配了、存量老版本没适配——老用户一打开就是白屏或闪退。规矩应该定成：**服务端任何对外接口变更，必须评估"线上最低存活的 App 版本还兼容吗"**，发布前把老版本装上真机连新服务端交叉验证一遍（向上兼容照顾新客户端读旧数据，向下兼容照顾老客户端访问新服务，两个方向都要想到）。这一格不占矩阵多少工时，漏掉一次就是一批老用户的"打开就闪退"。

## 举个例子

电商 H5 大促活动页上线前，你这样搭矩阵（用户数据来自埋点月报）：

- **浏览器**：Chrome 120（占比 38%）、Edge（12%）、Safari iOS 16（18%）、**微信内置浏览器（26%——最大的坑，X5 内核行为和标准浏览器不一样）**
- **机型**：小米中端（主力机型 21%）、华为高端（15%）、OPPO 两年前低端机（8%，代表低配档）
- **分辨率**：最小 360×640 和 2K 大屏各过一遍

两轮测下来捞出三个问题：微信内置浏览器里"分享给好友"面板调不起来（分享接口没做 X5 适配）；低端 OPPO 首屏 6 张大图加载 6 秒，用户流失风险；iOS 上输入收货电话时键盘把输入框顶出屏幕外。三个都提单，附上机型 + 系统版本 + 浏览器版本 + 复现录屏——兼容 bug 的提单要素和普通 bug 不同，**环境四要素缺一不可**，少一个开发就没法复现。

上线后微信升级了内核版本，你在自己手机上顺手回归一遍分享功能——**兼容性不是上线前突击一次，环境本身在持续变化**。

## 新手常见误区

| 误区 | 实际情况 |
| --- | --- |
| 兼容测试＝多买几台手机挨个点 | 用用户数据圈范围，凭手感买机器是浪费预算 |
| 模拟器过了就算过 | 模拟器复现不了 ROM 差异和真机性能，结论只能参考不能背书 |
| 只测最新系统版本 | 低版本用户占比常被低估；历史 bug 恰恰高发在老机型老系统 |
| 兼容是上线前突击一次的活 | 新系统发布、微信内核升级、热门新机型上市，都要触发回归 |
| 桌面端只用管 Chrome | 国产浏览器、Edge 兼容模式（政企用户真实存在）、Safari（苹果端独苗）都真实有人用 |

## 上手建议

1. 找运营或数据组要一份用户设备 TOP 10 报告，这就是你们团队兼容矩阵的骨架
2. 建一张团队机型矩阵表：高中低三档机型 + 分辨率两极 + 微信内置浏览器，每季度跟着用户数据更新一次
3. 注册一家云真机平台试用（多数有免费额度），把自己的模块跑一遍，体验真机远程调试
4. 微信生态的产品，内置浏览器永远进矩阵——它占比高且行为最"独特"
5. 兼容 bug 提单固定带环境四要素：机型 + 系统版本 + App / 浏览器版本 + 网络环境，外加录屏
