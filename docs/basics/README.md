# 测试八股文

> 写给刚入行和准备入行的你。后台被问得最多的问题——测试流程是什么、用例怎么设计、bug 单怎么提、测试报告怎么写——这里用人话一篇一篇讲清楚。**不用背，看懂就行。**

和站里另外两个板块各管一段：[学习路线](../roadmap/)告诉你**学什么、按什么顺序学**；[面试题库](../interview/)教你怎么把知识**组织成面试答案**；本板块负责中间那一步——**把每个概念本身讲明白**。三边互相链接，顺着读就行。

**用法建议**：按分类顺序读是最省力的路径，赶时间就直接搜你卡住的那个词。每篇都很短，通勤路上十几分钟能读完一篇，读完最好找身边的系统练一遍手。

## 每篇的固定结构

- **核心要点**：人话定义，先建立直觉
- **打个比方**：生活化比喻，把抽象概念落地
- **展开讲讲**：正经拆解，含表格和图
- **举个例子**：拿真实系统走一遍
- **新手常见误区**：踩过坑的人才知道的坑
- **上手建议**：明天上班就能用的动作
- **相关阅读**：链到路线对应章节和面试题库对应题目

## 与其他板块的边界

- 本板块讲「**是什么、为什么**」（概念科普，学习向）；[面试题库](../interview/)讲「**怎么答**」（场景应对，求职向）。同一个主题两边都出现时，八股文负责让你看懂，面试题负责让你答好
- 每篇文末的「相关阅读」会互相链接：八股文 → 面试题 → 路线章节，形成闭环

## 收录标准

- 每篇独立一个 Markdown 文件，英文 slug 命名，标题用中文
- 面向零基础读者，专业术语第一次出现必须给通俗解释
- 不鼓励背诵：写「为什么」比写「定义」多，例子必须来自真实可复现的系统场景
- 欢迎通过 Issue 或 PR 反馈你想看的概念，参见[贡献指南](/about/contributing.html)
