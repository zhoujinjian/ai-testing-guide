# 16｜经典思维题：怎么测电梯、水杯、微信红包

> 核心要点：这类题考的**不是用例数量，是拆解框架**——面试官想看你面对陌生对象时，能不能按**功能、界面、性能、安全、可靠性、易用性**六个维度有序展开，而不是想到哪说到哪。

## 打个比方

把答题过程想象成**体育裁判打分**。

跳水比赛裁判不是凭"感觉水花大小"打分，而是按**动作难度、完成质量、入水效果**几个固定维度逐项给分——每个运动员都过同一把尺子，分数才可比。你要是当场即兴发明标准，一场比赛一个尺度，金牌就没法发了。

"怎么测电梯"就是给你一个**没见过的运动员**。评委不要你背出全部动作，要看你**掏出尺子的动作熟不熟练**：掏出维度框架、按维度拆、每个维度下再分层——尺子对了，分数（用例）自然源源不断；没有尺子，说 50 条用例也是散装零件。

## 展开讲讲

### 万能六维度框架

任何对象都能套这六把尺子：

| 维度 | 问的问题 | 电梯的例子 |
| --- | --- | --- |
| **功能** | 它宣称能做的都做到了吗 | 上行下行、楼层按钮、开关门、超载报警、消防迫降 |
| **界面/交互** | 人看到的、摸到的是否对味 | 楼层显示、按钮手感、到站提示音、盲文按钮 |
| **性能** | 快吗、稳吗、扛得住吗 | 运行速度、平层精度、连续运行时长、能耗 |
| **安全** | 会不会伤人 | 门夹人感应、超载不停运、断电应急、困人救援 |
| **可靠性** | 坏了会怎样 | 故障自检、备用电源、平均无故障时间、维保周期 |
| **易用性** | 第一次用的人会不会懵 | 按钮高度、紧急呼叫流程、轮椅可用性、语音播报 |

外加两把针对软件对象的补充尺：**兼容性**（不同机型/系统/浏览器）和**可维护性**（日志、监控、配置）——测实物对象（电梯、水杯）时用不上，测软件对象（红包）时必须掏出来。

### 应答节奏：先问背景，再分层展开

高手和背题选手的第一个分水岭是**开口先问**而不是开口就答：

- "这部电梯的使用场景是写字楼、住宅还是商场？"（商场电梯要考虑购物车和小孩）
- "水杯是保温杯还是普通水杯？容量多大？给谁用？"
- "微信红包是发红包、抢红包还是红包零钱整体？测功能还是性能？"

**这一问就值一半分**——测试的第一课就是明确测试对象和范围（需求澄清），你把课堂知识用在了现场。问完再答，按六维度逐层展开，每个维度 2~3 条代表性用例，**宁可少而有序，不要多而散装**。

### 分层：每个维度内部再切

单个维度里继续用本系列学过的刀法，比如电梯"功能"维度里的超载报警——额定 13 人，那就是[边界值](./07-boundary-value-analysis.md)的地盘：12 人不报警、13 人报警、14 人必须拒绝关门。"安全"维度里的门夹人——那就是[错误推测法](./13-error-guessing.md)的雷区：婴儿车、宠物绳、手提袋带子，专挑检测盲区打。**框架给骨架，方法给血肉**，这才是 16 篇的合流处。

## 举个例子

三个对象各走一遍**骨架示范**（每维度只列代表用例，现场展开时补细节）：

**电梯（先问：写字楼载人电梯，额定 13 人）**：

| 维度 | 代表用例 |
| --- | --- |
| 功能 | 按 5 楼到达 5 楼平层误差 ≤ 5mm；13 人超载报警且门不关；消防按钮触发迫降 1 楼 |
| 界面/交互 | 楼层显示屏数字准确；到站音清晰；按钮盲文可辨识 |
| 性能 | 单层运行时间稳定；高峰连续 2 小时不停机；开关门时间恒定 |
| 安全 | 门遇障碍物回弹（用背包带测）；运行中断电轿厢照明应急启动；被困时紧急呼叫 10 秒内接通 |
| 可靠性 | 连续 10000 次运行无故障；故障时自动停靠最近层并开门 |
| 易用性 | 轮椅用户可够到按钮；第一次使用者无需指导会开关门 |

**水杯（先问：500ml 保温杯，成人使用）**：

| 维度 | 代表用例 |
| --- | --- |
| 功能 | 装 500ml 水不漏（倒置 10 分钟）；保温 6 小时后水温 ≥ 50°C（包装宣称值） |
| 界面 | 刻度线准确；杯盖螺纹顺滑无毛刺；logo 不掉色 |
| 性能 | 装满热水杯壁不烫手；10cm 高度跌落 3 次不碎不漏 |
| 安全 | 材质食品级（查 304 标识）；装沸水无异味；儿童误开难度 |
| 可靠性 | 开合 5000 次密封圈不老化；洗碗机清洗 100 次不变形 |
| 易用性 | 单手可开盖；杯口大小喝水不呛；车载杯架能放下 |

**微信红包（先问：抢红包功能，安卓/iOS 双端）**——软件对象，六维度换成软件尺子：

| 维度 | 代表用例 |
| --- | --- |
| 功能 | 发 200 元拼手气红包 10 份，金额之和恰为 200 元、每人最少 0.01 元；抢完显示"已抢完"；24 小时未领完退回原路 |
| 界面 | 红包开启动画流畅；金额展示精确到分；列表角标数量准确 |
| 性能 | 春晚级并发：万人同时抢一个红包不超卖不少发（金额总和守恒是**底线断言**）；接口响应 P99 < 500ms |
| 安全 | 金额篡改（抓包改参数）被拦截；不能抢非好友群的定向红包；未成年人支付限额拦截 |
| 可靠性 | 抢的瞬间断网：要么成功要么金额原额退回，**不出现"钱没了红包也没抢到"**；服务降级时提示友好 |
| 兼容/易用 | 双端体验一致；被移出群后红包入口表现正确；改用旧版本 App 交互不崩 |

注意红包那行的加粗——**并发守恒和断网一致性是这类题的高光用例**，说出来的那一刻，面试官知道你真的测过钱相关的功能。

## 新手常见误区

| 误区 | 实际情况 |
| --- | --- |
| 开口就狂列用例，一口气说 30 条 | 没有框架的罗列等于交白卷——面试官记不住也判断不了你的覆盖能力，**维度先行、用例殿后** |
| 不问背景，默认所有电梯一个测法 | 商场电梯、医用电梯、货梯差异巨大，**先澄清对象和范围**是测试第一动作，这步丢了减分最狠 |
| 六个维度背不齐，现场丢三落四 | 框架就六个词，背熟只要十分钟，丢维度等于裸奔上考场 |
| 只会功能维度 | 功能人人会列，**性能、安全、可靠性才是拉开差距的三板斧**，尤其是对象的"极端情况" |
| 用例停在"测保温"这类词上 | 没有数字就不算用例：保温多久、多少度、怎么验——**给每条用例配可判定的预期** |
| 把面试题当脑筋急转弯背答案 | 换个对象（测 ATM、测自行车、测二维码）就傻眼——**背框架不背对象**，框架才是可迁移资产 |

## 上手建议

1. **把六维度框架背到脱口而出**：功能、界面、性能、安全、可靠性、易用性——外加软件对象的兼容性，七个词，这是你所有"怎么测 XX"题的总开关
2. **每周自选一个新对象演练**：办公室的饮水机、地铁闸机、共享单车，按框架口头拆五分钟，坚持一个月，任何对象都不慌
3. **每维度至少备一个"高光用例"**：性能的并发守恒、安全的参数篡改、可靠性的断网一致性——这三个词组是你面试时的记忆点
4. **先问再答练成习惯**：找朋友互相出题，强制自己开口第一句是澄清提问而不是答案，练十次就定型
5. **对照面试题库演练口头表达**：[怎么测一个登录页面](../../interview/testing-essentials/04-login-page-test-design.md)的答题示范，把本篇框架和那篇的节奏合起来，形成你自己的三分钟答题模板
