# 15｜经典实战：登录、搜索、购物车用例设计

> 核心要点：这三个页面是**面试出现率最高的"三大件"**，也是把前 14 篇方法串起来用的最佳靶场——每页先看需求形状选方法组合，再落成用例表，**一套思路通吃百变问法**。

## 打个比方

把这三页想象成**驾考的三个必考科目**。

倒库、侧方、坡道定点——考试永远考这三个，因为它们把驾驶的**基本功全覆盖了**：方向感、距离感、离合控制。登录、搜索、购物车在测试界就是这个地位——**输入校验、结果匹配、流程与状态**，测试基本功的三块基石全在里面。练熟这三页，换任何新页面你都知道从哪下刀：先看它像三件套里的哪一件。

## 展开讲讲

### 三个页面，三套方法组合

| 页面 | 需求形状 | 方法组合 |
| --- | --- | --- |
| **登录** | 输入范围（账号密码规则）+ 状态（锁定/登录态）+ 流程（登录→跳转） | 等价类 + 边界值打底，状态迁移管锁定，场景法串登录后行为，错误推测补连点与记住密码 |
| **搜索** | 输入域（关键词）+ 结果匹配逻辑 + 交互（联想、历史、筛选） | 等价类切关键词，判定表管"关键词 × 筛选条件"组合，错误推测补特殊字符和超长词 |
| **购物车** | 数量范围 + 流程（加购→结算）+ 状态（商品下架/库存变化） | 边界值管数量，场景法铺下单链路，状态迁移管商品生命周期，错误推测补并发与脏数据 |

下面每页给一张**最关键的用例表**（每页 6~8 条，实际项目里一页铺 40~80 条很正常，这里是骨架）。篇幅有限，方法推导过程压缩成一句话，展开手法见各方法篇。

## 举个例子

### 一、登录页（规则：密码 8~16 位；连续输错 5 次锁定 30 分钟）

等价类 + 边界值切账号密码输入，状态迁移管锁定逻辑，错误推测补连点：

| 用例 | 输入与操作 | 预期结果 | 优先级 |
| --- | --- | --- | --- |
| 01 | 正确手机号 + 正确密码，点"登录" | 登录成功，跳转首页，昵称正确展示 | P0 |
| 02 | 正确手机号 + 错误密码 | 提示"账号或密码错误"，剩余尝试次数提示 4 次 | P0 |
| 03 | 密码连错 5 次 | 第 5 次提示"账号已锁定，请 30 分钟后重试"，30 分钟内正确密码也无法登录 | P0 |
| 04 | 锁定 30 分钟整后用正确密码登录 | 登录成功，锁定解除 | P1 |
| 05 | 手机号输入 `1380000111`（10 位，格式非法） | 点登录时提示"请输入正确的手机号"，不发请求 | P1 |
| 06 | 密码 7 位（低于下限 1 位） | 提示"密码至少 8 位"，登录失败 | P1 |
| 07 | 弱网下连点"登录"按钮 5 次 | 只发出 1 次登录请求，不出现多次跳转或闪退 | P1 |
| 08 | 勾选"记住密码"后退出再进 | 回填账号，密码不回填（明文回填是安全缺陷） | P2 |

04 那条"30 分钟整"是[边界值](./07-boundary-value-analysis.md)落在时间维度上的应用——"30 分钟后解锁"的临界点，分钟数取 29:59 和 30:00 各验一次更严。

### 二、搜索页（支持关键词、联想词、历史记录、结果筛选）

| 用例 | 输入与操作 | 预期结果 | 优先级 |
| --- | --- | --- | --- |
| 01 | 搜索"机械键盘" | 返回结果列表，标题含"机械键盘"的结果在前，总数与列表一致 | P0 |
| 02 | 输入"键"出联想词，点第一个联想词"键盘" | 跳转"键盘"的结果页，搜索框回填"键盘" | P1 |
| 03 | 搜索不存在的词 `zzzzqqq` | 展示空结果页"未找到相关商品"，推荐位正常展示，不白屏 | P1 |
| 04 | 搜索词含特殊字符 `<script>` 和空格串 `键盘 　膜` | 正常按关键词处理，无脚本执行，连续空格按一个处理 | P0 |
| 05 | 搜索 500 字的超长关键词 | 不报错，按前 N 字符截断搜索，或提示"关键词过长" | P2 |
| 06 | 搜过 3 个词后看历史记录 | 历史按时间倒序展示 3 条，可单条删除，删除后刷新不复活 | P2 |
| 07 | 关键词"手机" + 筛选"华为 + 2000~3000 元" | 结果全部满足筛选条件（[判定表](./08-decision-table.md)组合的典型落点） | P1 |
| 08 | 搜索瞬间断网再恢复 | 提示"网络异常请重试"，恢复后重试成功，不留残缺列表 | P2 |

04 和 08 是[错误推测法](./13-error-guessing.md)清单的直接产出——特殊字符和弱网，任何搜索需求都该扫一遍。

### 三、购物车页（数量 1~200，支持勾选结算、删除、失效商品置灰）

| 用例 | 输入与操作 | 预期结果 | 优先级 |
| --- | --- | --- | --- |
| 01 | 加购"无线机械键盘"1 件（库存 500） | 购物车出现该商品，数量 1，小计 299 元，角标 +1 | P0 |
| 02 | 数量输入框改为 `200`（上点） | 数量生效，小计 59800 元，结算按钮可用 | P0 |
| 03 | 数量输入框改为 `201`（离点） | 提示"最多购买 200 件"，数量回填 200，不进入结算 | P0 |
| 04 | 数量输入 `0` 和 `-1` | 提示"至少购买 1 件"，数量回填为 1 | P1 |
| 05 | 勾选 2 件商品点"去结算" | 结算页只含勾选商品，合计金额正确，未勾选的不出现 | P0 |
| 06 | 加购后商品被下架，再进购物车 | 该商品置灰标"已失效"，不可勾选，不能进结算 | P1 |
| 07 | 两台设备同时改同一商品数量 | 后提交的生效，购物车数据一致，不出现数量错乱 | P1 |
| 08 | 商品数量改为库存上限 500 以上的 600 | 提示"库存不足，当前库存 500 件"，数量回填 500 | P1 |

02、03 是[边界值](./07-boundary-value-analysis.md)五点法（1、0、199、200、201 取关键位）；06、07 是[场景法](./11-scenario-method.md)备选流与[错误推测法](./13-error-guessing.md)并发雷区的产物。

## 新手常见误区

| 误区 | 实际情况 |
| --- | --- |
| 背这三张表当标准答案 | 面试官随手改一个条件（"密码改成 6 位呢"），背答案就露馅——**背的是"形状→方法"的组合思路**，不是用例本身 |
| 只写功能正向，安全一概不提 | SQL 注入、明文密码、越权查别人购物车，这三页的安全用例是面试加分位 |
| 预期结果写"搜索正确" | 正确长什么样：顺序、总数、匹配度，写不出可判定标准的预期等于没写 |
| 忘了登录后的会话状态 | 登录成功只是起点：token 有效期、退出后回退键、多端互踢，都是登录需求的隐藏题 |
| 搜索只测"搜得到" | 搜不到（空结果）、搜出格（特殊字符）、搜一半（断网）这三态比搜得到更常翻车 |
| 购物车只测数量边界 | 加购→结算的流程断点（下架、库存变化、价格变动）才是购物车的主战场 |

## 上手建议

1. **亲自把三张表扩写一遍**：每页按方法组合扩到 40 条以上，写完和同事互评——这三页的完整版你练过一遍，测试基本功就过关了
2. **对着自家 App 找不同**：拿你项目的真实登录页，看它的规则跟本文有什么差异（验证码？多因素？），按差异重切等价类
3. **每页备一条"讲得出为什么"的用例**：面试被问"这条为什么这么设计"，能答出"201 是数量上限的离点，抓 `>` 写成 `>=` 这类错"才算真懂
4. **把三大件变成模板库**：这三页的用例结构（输入校验/状态/流程/异常）直接平移到任何新页面——注册像登录、列表页像搜索、订单页像购物车
5. **拿[面试题库](../../interview/testing-essentials/04-login-page-test-design.md)对照演练**：八股文教你懂，面试题教你答，两边对着读一遍，现场表达至少流畅一倍
