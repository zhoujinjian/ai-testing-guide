# 11｜场景法：沿着用户的故事走一遍

> 核心要点：用户不是一个个孤立地用功能，而是**沿着一条路径串着用**——搜索、加购、下单、支付。场景法就是把这条路径画成**基本流（顺利走通的路）+ 备选流（每一步可能岔出去的支路）**，逐条铺用例，专抓"单点都对、连起来断了"的流程型 bug。

## 打个比方

把场景法想象成**试营业前的"神秘顾客"走查**。

餐厅每道菜都通过了厨房试吃（单点功能都对），还不能开门——老板会雇神秘顾客**从进门到离店完整吃一顿**：门口迎宾接不接、点餐顺不顺、上菜快不快、中途退菜换菜会不会乱、结账开发票掉不掉链子。走查路线不是一条：一路顺的"标准顿"要来一次，**中途加菜、退菜、打折券用不了、上错菜**这些岔路，每种也要各来一次。

场景法就是测试的神秘顾客。**每个功能单测都对，只是及格线；用户从头走到尾的每一种走法都通，才是能上线**——而恰恰是功能交界处（下单页跳支付页时金额传错了、退回上一步时购物车数据丢了），最容易断。

## 展开讲讲

### 两块积木：基本流和备选流

| 概念 | 人话 | 电商下单的例子 |
| --- | --- | --- |
| **基本流** | 一切顺利时的主干路径，用户最常走的那条 | 选商品 → 加购 → 结算 → 付钱 → 下单成功 |
| **备选流** | 从基本流任何一步岔出去的支路：失败、取消、异常、回退 | 库存不足、优惠券不可用、支付超时、中途返回购物车 |

场景法的产出就是**基本流 + 各种备选流的组合**：一条用例 = 基本流走到底（最 Happy 的一条）；其余用例 = 基本流走到某步 → 钻进备选流 → 看它能不能**正确地回到主干或体面地结束**。

备选流的三个质量要求：

- **从哪岔**：明确挂在基本流的第几步
- **岔出去后去哪**：有的回到基本流继续走（如优惠券过期换一张再下单），有的直接终止流程（如库存不足放弃购买）
- **结束时世界是什么样**：订单状态、购物车数据、库存数据都要写进预期

### 走法四步

1. **画基本流**：按用户真实操作顺序，把最顺利的路径一步步列出来（用流程图更佳）
2. **挂备选流**：对基本流每一步问三遍——这一步会失败吗（库存不足）？用户会取消吗（中途关页）？数据会变吗（支付时另一端把商品下架）？每个"会"就是一条备选流
3. **组合场景**：备选流单独出场景；关键备选流之间再组合（优惠券不可用**且**库存不足）
4. **逐场景写用例**：每个场景一条（或几条）用例，预期结果落在**流程终点和沿途数据**上，不只落在眼前一步

### 场景法和单点方法怎么配合

场景法管**纵向**（一条流程走到底），[等价类](./06-equivalence-class.md)、[边界值](./07-boundary-value-analysis.md)管**横向**（每一步的输入域）。标准打法：先场景法把骨架场景铺全（保证路路通），再对每一步里的具体输入用等价类边界值加密（保证每步内的值也对）。一个管路、一个管站，缺一不可。

## 举个例子

电商 App 下单主流程，**基本流**：

> 1. 用户浏览商品详情 → 2. 加入购物车 → 3. 进入购物车点"去结算" → 4. 确认订单页（选地址、用券、算运费）→ 5. 发起支付 → 6. 支付成功 → 7. 订单生成，状态"待发货"

**挂出来的备选流**（对每步问三遍的结果）：

| 备选流 | 岔出点 | 走向 |
| --- | --- | --- |
| A1 商品库存不足 | 第 2 步 | 提示"库存不足"，加购失败，流程终止 |
| A2 商品在结算中被下架 | 第 4 步 | 提示"商品已下架"，从结算页剔除该商品，回到购物车 |
| A3 优惠券过期/不可用 | 第 4 步 | 券置灰提示"已过期"，可换券后**回到基本流**继续 |
| A4 收货地址为空 | 第 4 步 | 引导新增地址，填完**回到基本流** |
| A5 支付超时未付款 | 第 5 步 | 订单保留 15 分钟，超时自动取消，库存回滚 |
| A6 支付中途退出 App | 第 5 步 | 重进后可从"待支付订单"继续支付 |
| A7 支付失败（余额不足） | 第 5 步 | 提示"余额不足"，可换支付方式**回到基本流** |

**逐场景写用例**（节选最重要的六条）：

| 用例 | 场景路径 | 步骤要点 | 预期结果 | 优先级 |
| --- | --- | --- | --- | --- |
| 01 | 纯基本流 | 选"无线机械键盘"→ 加购 → 结算（默认地址、不用券）→ 支付宝付 299 元 | 支付成功页展示订单号，订单列表出现状态"待发货"，库存 500→499 | P0 |
| 02 | 基本流 + A2 | 加购后，后台将商品下架，再进结算页 | 提示"商品已下架"，结算页无该商品，返回购物车该商品置灰 | P1 |
| 03 | 基本流 + A3 | 结算页选一张已过期券 | 该券置灰，提示"优惠券已过期"，改选可用券后金额按 269 元计算，后续流程正常走通 | P1 |
| 04 | 基本流 + A4 | 删光收货地址后进入结算页 | 提示"请添加收货地址"，新增地址保存后自动带回结算页，其余信息不丢 | P1 |
| 05 | 基本流 + A5 | 下单后不付款，等 15 分钟 | 订单自动取消，状态变"已取消"，提示"超时未支付"，库存回滚为 500 | P0 |
| 06 | 基本流 + A7 | 支付宝余额 0 元支付 299 元订单 | 提示"余额不足，请更换支付方式"，换微信支付后成功，订单"待发货" | P1 |

看用例 05 和 03 的预期：场景法的预期结果**不写在这一步，写在流程终点**——订单最终状态、库存数字、金额，这些"世界的终态"才是业务真正在乎的。用例 02 那种"结算中途商品被下架"的场景，任何单点方法都够不着，只有沿着流程走才撞得见——**这就是场景法不可替代的原因**。

## 新手常见误区

| 误区 | 实际情况 |
| --- | --- |
| 场景法 = 把主流程测一遍 | 只测基本流是最常见偷懒，**价值全在备选流**——失败、取消、回退、并发才是事故源头 |
| 备选流只写"失败了"不写"然后呢" | 岔出去能不能回主干、终态数据对不对，才是场景法要断言的重点 |
| 预期结果只看眼前这步 | 下单页拦截成功了，但购物车数据被误清——终态校验（订单表、库存、购物车）必须写进预期 |
| 场景组合无脑全排 | 备选流两两组合就有几十种，按风险挑：高频 × 高损的组合优先，长尾交给回归抽样 |
| 画了流程图就收工 | 图是设计工具，每个场景最终都要落成带输入值和终态断言的用例 |
| 只画"用户的"场景 | 商家发货、客服改价、系统对账这些**非用户视角的流程**也是场景，电商大事故常出在这 |

## 上手建议

1. **给你负责的模块画一张基本流图**：泳道图或简单流程图都行，画完贴在工位，备选流往上面挂
2. **备选流三问清单固定下来**：每步"会失败吗、会取消吗、数据会变吗"，照单扫基本流，备选流一条不漏
3. **终态断言模板化**：每个场景的预期末尾固定挂三查——订单状态、关键表数据、消息通知，养成肌肉记忆
4. **拿客服工单反哺场景库**：用户真实撞到的诡异路径（先下单再删地址）就是最鲜活的备选流素材
5. **流程型场景优先自动化**：基本流 + 高频备选流（01、03、05 这类）是回归自动化性价比最高的对象（怎么起步见[实战教程](../../knowledge/)）
