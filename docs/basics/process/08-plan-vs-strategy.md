# 08｜测试方案与测试策略的区别

> 核心要点：**测试策略回答"我们长期怎么测"，测试方案回答"这个版本具体怎么打"**——一个是方针，一个是作战图；分不清的人写出来的方案全是口号，落不了地。

## 打个比方

像**一支球队的两种文档**。

赛季开始前，教练组定**赛季策略**：今年主打防守反击、青训队员进入轮换、每场跑动不低于 110 公里、定位球得分要占三成——管一整个赛季，全是原则和方针，不会因为输一场球就推翻。

到了具体一场对强队的比赛，有**单场部署**：这场谁首发、谁贴身盯对方 10 号、落后 60 分钟就换人变阵、角球抢前点——管这一场，具体到人和分钟，每场重写一份。

策略错了，每场部署再精致也是输（方向问题）；方案错了，好策略也赢不下这场（执行问题）。两者谁也替不了谁。

## 展开讲讲

### 先给两个定义

**测试策略（Test Strategy）**：组织或产品线级别，回答"质量怎么守"——测试类型怎么组合、自动化走什么路线、环境怎么规划、质量门禁定什么标准。周期以年计，相对稳定。**测试方案（通常对应 Test Plan 的技术部分）**：项目或版本级别，回答"这一次怎么测"——范围、人力排期、用例设计方法、环境和工具、准入准出。每个版本一份。

### 逐项对比

| 维度 | 测试策略 | 测试方案 |
| --- | --- | --- |
| 层级 | 公司 / 产品线 | 项目 / 版本 |
| 回答 | 长期方向：测法怎么组合 | 单次落地：这版具体干什么 |
| 周期 | 一到几年，少量修订 | 每个版本重写一份 |
| 内容风格 | 原则、标准、路线 | 动作、清单、日期、责任人 |
| 谁来写 | 测试负责人 / QA 经理 | 该版本的测试负责人（可能就是你） |
| 典型句子 | "核心链路接口自动化覆盖率不低于 80%" | "本次新增 12 个券接口全部补自动化，小李负责，2 天完成" |
| 变更方式 | 年度评审微调 | 随需求变更即时更新 |

### 关系：方案是策略的实例化

策略说"核心链路必须有自动化兜底"，每个版本的方案里就该有一节"本次新增功能的自动化计划"。**校验自己方案的方法**：逐条问"这个动作对应策略里的哪条原则"——全对不上号，要么方案跑偏了，要么策略该修了。反向也成立：策略里写了两年"兼容性覆盖 Top10 机型"，方案里从来没有这一节，说明策略在空转。

### 策略里最该定清楚的五件事

如果你有机会起草策略，这五件最值得写透：**自动化路线**——哪些层自动化、覆盖目标多少、用什么框架（别只写"大力投入自动化"这种空话）；**环境规划**——几套环境、谁维护、数据怎么脱敏；**质量门禁**——流水线上哪些卡点、什么数字标准；**专项节奏**——性能压测多久做一次、安全扫描什么时候必跑；**分工模型**——测试跟项目走还是跟模块走。每一条都要能回答"谁执行、多久一次、达标线在哪"，答不上来的策略条目就是墙上的装饰品。

### 和"测试计划"什么关系

不同团队叫法不统一：有的团队方案和计划是一个东西（Test Plan 的两种翻译），有的团队拆开——计划偏管理（范围、排期、准出，见[上一篇](./07-test-plan.md)），方案偏技术（怎么设计用例、怎么搭环境、自动化怎么铺）。**入职第一周先问清团队的叫法**，别在名词上跟人吵架。你只需要握紧一层关系：**策略在上、方案在下，方案必须能向上追溯到策略**。

## 举个例子

某电商公司的两层文档对照着看。

**策略层**（2026 年版节选）：① 交易核心链路接口自动化覆盖率不低于 80%；② 每年两次大促前必须做全链路压测；③ 新功能冒烟自动化进流水线作为部署卡点；④ 兼容性覆盖 Top10 机型。

**方案层**（「双 12 优惠券叠加」版本节选）：

- 对应策略 ①——本版本新增 12 个券接口全部补自动化（小李，2 天，挂流水线）
- 对应策略 ②——全链路压测排在 11 月 20 日，目标 5000 QPS，重点压券核销接口
- 对应策略 ③——冒烟集合从 26 条扩到 38 条，全绿才准部署预发
- 对应策略 ④——Top10 机型在新版购物车页做专项走查，小周负责半天

方案里每个大动作都能向上找到策略出处——这就是"落地"的样子。反过来，如果方案里写着"加强质量保障，严控线上风险"却没有一条具体动作，那就是把策略的口号抄进了方案，两头落空。

## 新手常见误区

| 误区 | 实际情况 |
| --- | --- |
| 策略和方案是一回事 | 层级、周期、内容全不同，混着写会两头落空 |
| 方案写成口号集 | "确保质量、严控风险"没有动作，方案要能照着干活 |
| 策略定完永不改 | 自动化比例、机型分布、团队规模都在变，策略要年度体检 |
| 小团队不需要策略 | 三个人也该有半页纸共识，不然每个版本都重新吵一遍 |
| 策略是负责人一个人的事 | 一线执行的可行性只有执行者知道，定策略时你该在场 |
| 方案必须面面俱到 | 完整度跟着版本风险走，小改动版本半页纸方案也合格 |

## 上手建议

1. **找到团队的测试策略文档通读一遍**，摘出和日常工作直接相关的 3 条贴在笔记里
2. **给自己手头的版本写半页方案**，逐条标注它对应策略的哪一条
3. **团队没有策略的话，试着起草半页纸**：自动化怎么推、兼容性怎么测、门禁怎么定——这半页纸会让你在 leader 眼里上一个台阶
4. **入职新团队先问清叫法**："咱们这儿方案和计划是一个东西吗？"一句话避免半年名词打架
5. **面试前用"方针 vs 部署"框架**把两者各讲 30 秒，能顺带讲"方案要能追溯到策略"就是加分项
