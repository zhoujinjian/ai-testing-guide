# 参与共建

如果你也是测试开发的实践者、AI 探索者，并且乐于分享你的实战经验与踩坑记录，欢迎加入共建，一起打磨属于 AI 时代所有测开人的成长路线。

**你将收获**：影响力提升、深度学习、价值认同（贡献明确署名）、拓展人脉。

## 如何贡献

### 提 Issue

适合这类贡献：

- 内容纠错：事实错误、过时信息、失效链接
- 内容建议：希望补充的主题、阶段、工具
- 资源推荐：好的教程、书籍、开源项目

提 Issue 前请先[搜索](https://github.com/zhoujinjian/ai-testing-guide/issues)是否已有同类 Issue，避免重复。

### 提 PR

适合这类贡献：

- 修复错别字、格式、失效链接
- 为现有章节补充「推荐资源」
- 新增知识点文章（放入 `docs/knowledge/`）

PR 流程：

1. Fork 本仓库
2. 基于最新 main 分支创建特性分支
3. 完成修改，保持每章原有模板结构（为什么重要 / 知识清单 / 学习建议与常见误区 / 自查清单 / 推荐资源）
4. 提交 PR，标题用一句话说清改了什么

每个页面的「编辑此页」链接会直接定位到 GitHub 上对应的源文件，随手就能改。

## 内容规范

- 文件名使用英文 slug（如 `playwright-in-action.md`），标题使用中文
- 推荐外部资源时优先官方文档、权威书籍、活跃维护的开源项目
- 涉及工具版本的内容注明适用时间（如「2026-08 时 Playwright 版本为 1.x」）
- 不接受与学习路线无关的广告、招聘类内容

## 想深度参与

加作者微信（见[关于本路线](./README.md)中的二维码），备注「共建」，一起认领[技术分享](../knowledge/)等板块的规划主题。

## 协议

提交 PR 即表示你同意内容以 [CC BY-NC-SA 4.0](https://creativecommons.org/licenses/by-nc-sa/4.0/deed.zh) 协议发布。
